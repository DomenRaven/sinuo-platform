# 00 施工总览与完成标准

版本：2026-10-30。本文件是编码代理的入口。读完后再读 `02_基线裁决与勘误.md`，然后按认领的任务卡读对应合同。

## 1 要交付什么

P0 是可运行的后端，不是文档。从空数据库迁移启动后，一条有授权的工业设计项目必须能走完：

建项目与平行页 → 保存版本与原件 → 形成可定位证据 → 按任务调用最多三种职责 → 生成合法候选 → 具权者确认且只生效一次 → 从历史版本开新分支 → 授权审阅 → 导出与备份恢复。

每一步都要有真实 API、数据库状态和可重复的测试。FakeProvider 只能证明编排规则，不能代替持久链、权限和恢复。

## 2 本轮不做

- 产品页面、动效和视觉设计。后端通过 G4 后，UI 交回专门阶段，交接清单见 `52_运行部署与UI交接.md`。
- P1/P2（概念发散、工程结论、常驻八角色、自动评分）只登记，不占用 P0 验收。
- 真实 DeepSeek 调用。默认关闭；确定性测试用 FakeProvider。

## 5 骨架现在做到哪

已实现并有测试：配置与密钥不进日志、`/healthz`、`/readyz`（仅 foundation）、迁移 `0001_primitives` 的三张基础表与 `0002_lease_invariants` 的租约约束、短 `BEGIN IMMEDIATE` 写事务、幂等命令存储、Outbox 租约与 fencing、内存有界 DAG runner、关闭状态下明确失败的模型接口。

2026-10-30 已补进骨架、后续实现不得退回：

- `asyncio.wait_for` 超时后，即使 Provider 吞掉取消并返回，结果也记 `DEADLINE_EXCEEDED`，不进入 completed。
- 同一运行内职责必须是 clarification、evidence、method、critic 之一，且互不重复，总数不超过 3。
- Provider 返回的 `task_id` 或 `role` 与任务不符时拒绝。
- `write_uow` 内部自行 commit 会被拒绝并回滚。
- `/readyz` 在缺表、多版本号或版本不符时返回 503，不报可用。

未实现：业务 API、真实 ACL、持久 AgentRun、SSE、原件与派生件、检索、DeepSeek 传输、候选提交、审阅、导出和恢复。不要把骨架测试写成 P0 已完成。
