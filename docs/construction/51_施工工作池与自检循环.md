# 施工工作池与自检循环

版本：1.1｜2026-10-30。这里管理的是开发代理的任务，不是产品运行时的 Worker 队列；二者必须使用不同的目录、ID 和状态表。

## 1 工作池结构

`workpool/BOARD.md` 是当前进度入口；`workpool/tasks/` 保存目标任务卡；`workpool/decisions/` 保存改变公共合同的 ADR；`workpool/handoffs/` 保存上下游交接。测试日志、临时脚本和截图按项目的施工目录规则保存，只保留能重现失败或证明门禁的必要材料。

每张任务卡至少记录：任务 ID、目标、上游、owner、精确写入范围、输入合同、可交付结果、验收条件、风险、状态、证据与下一步。主控负责调整 ready 队列和任务依赖，开发代理负责更新自己任务卡，集成 owner 负责最终合入与 done 判定。

## 2 状态与转移

`planned → ready → claimed → implementing → review → verify → done`

失败可以回到 `implementing`。外部条件缺失时进入 `blocked`；上游合同变化时进入 `needs_rebase`，重新验证后回到合适阶段。不存在用“基本完成”代替 `done` 的状态。

| 状态 | 进入条件 | 留下的记录 |
| --- | --- | --- |
| planned | 目标已知，上游未齐 | 缺失依赖与预期接口 |
| ready | 上游已交接，写入范围无冲突 | 基线提交/快照、输入合同版本 |
| claimed | 主控分配或代理认领成功 | owner、开始时间、文件范围 |
| implementing | 最小方案明确，正在改代码 | 当前假设、具体改动、运行命令 |
| review | 自测完成，可供独立审查 | diff、验收证据、已知限制 |
| verify | 阻断性审查问题已处理 | 审查结果、修复与回归命令 |
| needs_rebase | 基线或上游合同变化影响本任务 | 旧/新合同差异、受影响测试、重新认领与验证计划 |
| done | 集成后验收通过且交接齐全 | 合入引用、测试结果、下游入口 |
| blocked | 需外部资料/授权/工具或产品决策 | 精确阻塞条件、已尝试路径、可继续任务 |

工作池采用“一个任务一位写入 owner”。主控可让审查者并行只读检查。认领锁只是施工协调，不提供产品并发安全；产品正确性仍依赖数据库约束与事务。

## 3 一次自检循环

1. 从 ready 中选上游最完整、能消除最多下游阻塞的任务，确认文件所有权。
2. 读该任务的验收条件，写下最小实现路径与风险；未知实现细节可用小实验查证。
3. 完成一个可运行增量，运行与本次风险相关的测试；保留命令、退出码与失败证据。
4. 交独立审查者检查边界、竞态、权限与错误恢复。审查意见必须能指向代码、契约或可复现反例。
5. 修复阻断性问题，运行针对性回归，再由集成 owner 合并并运行消费者测试。
6. 更新任务卡与 BOARD，解锁下游，继续下一个 ready 任务。

当一次尝试失败时，先记录“观察到什么、支持哪种假设、下次改变哪一个条件”。连续三次遇到同一失败且没有新增证据，停止重复同一做法，进入诊断模式：缩小复现、检查上游假设、阅读官方资料，或重新分配专责审查。诊断得到新证据后可以继续；仍需外部输入则标 blocked，同时推进独立任务。禁止无限重试、无限扩大任务范围或通过删测试/放宽断言伪造通过。

## 4 自主权与必要边界

开发代理可自行选择函数结构、算法、局部依赖、查询优化、缓存实现、测试夹具、重构和调试路径，只要符合冻结行为和验收。替换既定模块栈、改变公共接口、升级会影响兼容性的依赖时，由主控用简短 ADR 记录理由、替代方案、迁移和回归，再继续实施；无须因每个实现选择向用户确认。

必须保留的约束包括：历史不可静默覆盖、业务写入经过授权命令、模型工具只读、候选需人工确认、单运行最多三种职责、原件可靠保存、任务租约与迟到结果隔离、幂等与事件重复投递可恢复、UI 延后。任何真实外发资料、付费模型调用和密钥使用仍遵循用户已授权范围；没有可用凭据时使用 fake provider 完成工程验证并明确标记。

## 5 验收与记录纪律

自动测试证明的是实际断言，模型审查证明的是发现了哪些问题。两者不可互换。每个 done 至少有一次在集成基线上执行的可重复验证；压力、时延、成本和模型效果没有实测就写待测。

每轮只更新当前任务卡和一份简短交接；必要日志链接到施工目录，不生成大量重复“总结”。完成任务后清理代理创建的临时文件，保留来源、关键失败复现、迁移和验收记录。不得因瘦身删除用户原件、锁定文档、秘密配置、数据库或唯一测试证据。

## 6 会话中断后的恢复

恢复时先读 BOARD，再读 claimed/implementing/review/verify/blocked 的任务卡、未合入 diff 与最后一次测试结果。核实文件状态后重新认领；不能依据上一轮口述直接标 done。没有后台执行工具时，“自循环”只在当前会话内持续，不声称对话结束后仍有代理或定时任务运行。


## 7 真实执行与恢复入口

按施工53探测真实宿主能力，workpool/SESSION.md记录模式、真实代理/进程、文件owner、基线、最后命令/退出码、审查待办与下一动作。默认主控+两开发+独立只读审查，按实际槽位调整。开发槽位数不等于产品职责上限。无真实子代理如实顺序执行，无后台不承诺会话结束后继续。当前SESSION是待Grok填写入口，不能把模板当运行证据。
