# 06 身份、权限、原件存储与恢复施工合同

状态：施工基线，2026-10-30。与 03 领域事务、04 API、05 工作流共同实施。本文件规定 P0 的可验证边界；实现者可以优化内部结构，权限结果、原件不变量和恢复结果须保持一致。

## 交付目标

设计师可在授权项目中保存资料、找回准确版本、发起有边界的模型任务、留下可追溯决定。其他项目、旧会话、旧候选、缩略图、搜索索引、运行事件和导出均不能成为读取受限资料的旁路。完整项目应能从数据库备份与原件清单恢复，恢复后仍保持当前授权和已生效的隐私删除。

## 身份与会话

P0 使用本地账号和服务端持久会话。密码由 `argon2-cffi` 的 Argon2id 实现哈希与验证，参数由配置冻结，登录成功时按库推荐版本判断是否需重新哈希。数据库只存密码哈希。创建首位维护者通过本机 CLI 的交互式密码输入完成；不植入默认密码，不在命令行参数、日志或示例数据中留下真实密码。P0 账号创建、禁用和密码重置由维护者 CLI 或已授权管理命令完成，邮件找回与第三方登录留待后续。

会话令牌使用至少 32 字节加密安全随机数，浏览器持有原令牌，数据库只保存其 SHA-256、用户 ID、创建/最后活动/到期时间、撤销时间和认证纪元。会话有空闲和绝对期限，起始配置可采用 8 小时空闲、24 小时绝对期限，作为可调整产品参数记录。登录成功轮换令牌；退出、账号禁用、密码重置使相关会话失效。认证失败对外使用统一错误，登录限速同时考虑账号与来源，内部日志留错误类别而不存密码。

浏览器使用 host-only、`HttpOnly`、`SameSite=Lax` Cookie；HTTPS 部署加 `Secure`，可使用 `__Host-` 前缀并固定 `Path=/`。本机 HTTP 开发使用明确的开发 Cookie 名，默认监听 `127.0.0.1`；不得在 HTTP 模式假设 `__Host-` Cookie 已生效。修改业务的 Cookie 请求须验证精确允许的 Origin 和与会话绑定的 CSRF token。登录接受 JSON，校验 Origin 并限速；登录后的 CSRF token 经同源会话详情端点返回。默认不开放跨源凭据；不能使用 `Access-Control-Allow-Origin: *` 配合 Cookie。

测试身份替换只在 pytest 依赖注入中启用，生产应用不得注册该替换。P0 不提供开发身份 HTTP 旁路；若实现者引入开发认证开关，生产启动必须明确拒绝它。未引入该开关时，须用生产应用实例证明伪造开发身份头/参数不能认证，不能把“没有开关”写成已测过拒绝开关。此项由 T02 实现验收。登录、登出和会话读取属于身份生命周期，不套用业务命令幂等回执；退出重复调用保持安全无副作用。其余修改命令沿用 03 的幂等合同。

## 权限决策与主体边界

有效授权为：有效账号/会话 ∩ 项目成员范围 ∩ 对象动作授权 ∩ 字段敏感级别 ∩ 对象当前可用状态。项目角色只展开一组默认动作，不能代替对象授权。默认拒绝；禁止从请求中的 `role`、`actor_id`、文件路径或模型输出推导权限。所有读服务与只读工具共同调用同一授权服务。

| 主体或动作 | 服务端检查 | 可见结果 |
| --- | --- | --- |
| 项目成员 | 成员状态、project.read、分配页范围 | 授权页与元数据投影 |
| 设计负责人确认 | decision.confirm，加目标 page/stage 写权限和所有来源读取权限 | 有权限的预览与正式提交 |
| 资方/评审 | 共享里程碑及对象授权；opinion.create 单独授权 | 共享内容与自己的审阅意见 |
| 原件下载 | artifact.original.read 与确切 artifact_version_id | 授权字节流，不暴露磁盘路径 |
| 预览与搜索 | preview.read / evidence.read，重新检查源对象 | 授权缩略图、片段和定位；隐藏对象的标题、计数也隐藏 |
| 模型运行 | 发起者权限裁剪后的 scope，加资料外发策略 | 五个只读工具及限定片段 |
| 派生 Worker | 任务指定对象、转换能力、当前未被删除/隔离 | 相应派生件；无项目领域命令权 |
| 导出 | report.export，加逐项来源与输出内容权限 | 已授权输入快照的导出；下载时再查权限 |

核心动作枚举包括 `project.read/create`、`stage.configure`、`page.create/read/draft.write/checkpoint/branch`、`decision.confirm`、`artifact.upload/original.read`、`preview.read`、`evidence.read/create`、`run.create/read/cancel`、`test.record`、`opinion.create/edit_own`、`report.export`、`acl.manage`、`privacy.delete`。具体枚举可按语言惯例组织为常量；调用处不可使用任意字符串绕开检查。

页版与其证据原件分别授权。有权看页而无权看访谈时，仅返回页本身允许公开的内容；原文、嵌入摘录、标题、缩略图及聚合计数都按敏感级别裁剪。作者同样需要当前权限才能修改自己的审阅意见。P0 跨项目引用直接拒绝，不能依靠“用户同时是两个项目成员”隐式扩大某次运行范围。

## 撤权与正在执行的任务

ACL 修改在短事务中更新授权和 `project.access_epoch`，同时写审计/Outbox。新 ACL 从事务提交起立即用于读授权，缓存清理事件只是加速手段。缓存键至少含主体、项目、对象版本和访问纪元；敏感响应使用 `Cache-Control: no-store`，原件下载走当前授权代理，P0 不签发可长期绕过 ACL 的公共链接。

工具读取、模型外发前、候选发布前、预览与提交、SSE 新数据/重放、导出生成/下载均检查当前权限与对象状态。若授权纪元在读取和发送之间改变，重做投影或结束响应；已经发出的字节无法召回，验收验证撤权后的新受控读取会被拒绝。历史权限快照只是说明当时的输入。

撤权影响的正在运行任务转入取消或局部失败；其晚到输出只存安全诊断与实际用量，不发布原文或可提交候选。已生成的报告与候选默认继承所依赖资料的可见性，不因“AI 改写过”自动降级为公开。需要共享摘要时，由具权者执行显式脱敏发布动作，保留版本与依据。

## 原件、暂存与派生目录

运行数据根由 `SINUO_DATA_DIR` 配置为项目目录内受控位置，默认 `var/`；真实凭据来自服务端环境变量。目录是物理存储，不直接暴露为静态 Web 路径。建议结构：

```text
var/
  sinuo.db
  objects/<project_id>/sha256/<prefix>/<hash>/<generation_id>/original
  uploads/<upload_id>/<attempt_id>.part
  derived/<project_id>/<artifact_version_id>/<generator_version>/<content_hash>
  jobs/<job_id>/<fencing_token>/
  exports/<export_job_id>/<manifest_hash>/
  quarantine/
```

文件名只是元数据；对象键由服务器生成。所有路径规范化后检查在配置根内，拒绝 `..`、绝对路径、符号链接/重解析点跳转和不可信文件名参与目录拼接。内容寻址只在项目内去重，避免跨项目存在性推断。原件哈希由服务器流式计算；客户端声明只作校验。下载提供安全的文件名，设置 `nosniff`，活跃内容使用附件方式，预览使用受控派生格式。

上传有文件大小、项目容量、并行上传数、票据有效期与请求时限，超过上限在消耗完整资源前停止。数据库与文件系统不能组成单一事务，因此使用“两阶段登记”：

1. 有权限者申请上传票据，登记 upload_id、项目、逻辑作品 ID、许可和敏感级别。
2. 字节流进入隔离暂存，计算哈希、大小与格式；格式声明与实际检测不符则进入明确失败/隔离状态。
3. 校验完成后，先为目标 object/generation 建立上传 reservation/pin；长字节写入、哈希与格式校验均在事务外完成到同卷 attempt 暂存。最终短事务重查 pin/对象 state/fence、票据归属、当前权限及容量/版本预条件，执行不覆盖目标的同卷原子安装，切换 reserved→ready，登记 ArtifactVersion、ProjectRevision、审计与 Outbox 并消费 pin。
4. 事务成功后才可引用；失败对象保持不可达。清理器按下述同一对象状态协议认领无引用且超过安全期限的对象；不得只用文件年龄或一次引用复查决定删除。

同名新内容创建新版本；不同路径的相同内容可在同项目内复用字节，但保留各自的业务版本/许可关系。预览失败不影响原件取回，原件损坏也不能用旧缩略图伪装正常。API 分别返回 original、preview、extraction、index 的状态和失败原因。

## 预览、抽取与专业文件

P0 自动预览范围冻结为常规栅格图片、PDF、GLB。图片使用 Pillow，限制像素数、解码大小并移除默认展示中的敏感元数据；PDF 使用 `pypdfium2` 按限定页数/尺寸渲染，文本抽取记录页码与生成器版本。GLB 由受控 Blender CLI 转换器生成封面，先探测工具版本和可用性；未安装时标记能力不可用。对 F07 的最终验收仍须在目标环境完成至少一个 GLB 自动预览，不以占位图代替。

转换进程使用参数数组和固定脚本，不走 shell 拼接，禁止用户提供脚本/插件路径；设超时、输出大小和可用的 OS 进程资源限制，终止时清理子进程。GLB 的纹理/缓冲资源必须来自同一上传对象允许的资源范围，不解析任意外部 URL。PDF、图片和 3D 限额由测试确定并配置。没有可靠低权限隔离的演示环境只对明确可信样例启用转换，并如实记录部署限制；不能把普通 subprocess 描述为完整沙箱。

Figma、PSD、AE、PR、SolidWorks、CAD 等原件在 P0 可存储、版本化、下载并附用户提供的可信封面，记录封面来源。此流程不等同于完整解析工程语义。OCR、音视频转写、更多 CAD 格式、自动工程判断按 P1/P2 再接入。手动证据定位和文本摘录仍可用于 P0。

## 搜索、记忆和模型数据外发

P0 使用 SQLite FTS5 与关键词检索。中文不能仅假定 `unicode61` 等于有效中文分词：实现启动探测 FTS5/trigram 能力，长度足够的查询采用 trigram；短查询采用已授权候选集内有界、转义后的子串检索，或用已验证中文分词适配器。无论选择哪种方案，都须在固定中文样例上报告召回和锚点正确性。检索范围、版本、当前授权应进入 SQL 过滤/候选集计算；显示前再复核源对象。不能先把全库片段交给模型再让模型删掉无权限内容。

索引行保存 project_id、源对象版、锚点、生成器/索引修订、内容哈希。删除和撤权立即由查询权限限制生效，随后异步清理派生内容。历史摘要退出默认当前检索；查询旧版时仍按当前权限裁剪。运行读集由不可变初始快照与实际读取账本共同组成，来源详情按 05 合同保存。

DeepSeek 仅通过服务端 `ModelProvider`/适配器访问官方配置的 HTTPS 端点。API key 不进入前端、本地资料目录、提示词、日志或 Git；模型名、能力探测、错误映射和预算受配置控制，不能由上传文档覆盖。P0 不假设 DeepSeek 提供向量 embedding 服务，首版检索不依赖它。外发前核对项目/资料的 `ai_processing_allowed`、敏感级别与本次目标提供方；禁止外发的资料可保存在项目中，但不进入模型上下文。

工具片段、用户文件和历史对话均作为不可信数据，不能改变系统工具白名单、权限或运行预算。模型只获得需要的只读 Schema；所有候选锚点、版本与动作再由服务器校验。配置的模型上下文上限不等于应用应发送的 token 数。不得在供应商失败时把完整提示词写进异常日志。

## 数据保留、隐私删除与备份

普通“放弃路线”、回溯、合流保留历史。合法隐私删除分两段：授权命令先写墓碑、撤销读取、使受影响候选/导出失效并发布清理任务；Worker 再清理原件、预览、摘要、索引、缓存和可删除的外发临时副本。墓碑仅留对象身份、失效类别、时间和审计号，不保存被删正文。共享物理字节必须按同项目有效引用/保留要求决定清理；不可误删其他有效版本的对象。

备份通过 SQLite Online Backup API 或经过测试的一致性备份流程读取数据库，禁止在写入中直接复制单个 `.db` 并忽略 WAL。备份 manifest 至少记录 schema revision、数据库哈希、ProjectRevision 集、所有可达原件对象键/哈希/大小、备份时间、配置格式版本和删除墓碑纪元。原件不可变，使数据库快照的可达对象集合能够随后逐一复制；复制后验证清单。预览/索引可选择不备份，恢复后重建。

恢复到新空目录，校验数据库、迁移兼容性、外键完整性和清单每个原件哈希；启动前作完整性检查。会话全部失效，Worker 租约复位为待恢复而非保留旧活跃 owner，重复投递按幂等合同处理。恢复旧快照前应应用当前有效的隐私删除清单，防止旧备份复活已删除资料；若最新删除清单不可得，恢复项目保持离线，待维护者核验后再开放。此限制写入恢复报告，不能假报全自动恢复成功。

完成一次真实恢复演练，验证含分支、多个作品版本、证据、审阅意见、候选处置和权限的项目。记录备份耗时、恢复耗时、恢复时点与丢失窗口，据此给出实测 RPO/RTO；施工合同不预先声称“零丢失”。备份归档与用户原件的清理由具权者配置保留期并审计，开发代理不自行删除真实资料。

## 发布门槛与交接

本文件的控制由 07 的权限、上传、撤权、转换和恢复测试验证。任何业务路由上线前必须有相应未授权、跨项目、撤权和版本错误测试。模型开启前记录提供方、模型、外发范围与预算；在无真实密钥的环境，FakeProvider 可验证控制流，但真实模型验收标记待运行。交给后续 UI 的只有明确 Schema、状态、权限投影和错误示例，不以隐藏前端按钮代替服务器控制。

## 原件登记与清理的并发协议（T05）

`StoredObject` 以 object_id 标识一次物理生成，另存 project_id、sha256、generation_id、state、fencing_token；ArtifactVersion 引用 object_id 并保存校验哈希。同项目同哈希可复用 ready 对象；重建已清理对象必须分配新 generation_id 和新物理路径。相同内容的不同 generation 仍具有相同内容哈希，generation 只隔离物理生命周期。

状态为 reserved → ready → gc_claimed → deleted；错误另记 quarantined。上传写入新 generation 前须建立有效 reservation；引用已有 ready 对象前也须建立有期限的 pin。所有 pin、引用登记和 GC claim 使用同一数据库与短写事务串行化。GC 仅在无有效业务引用、无有效 pin、超过保留期时 CAS ready/reserved → gc_claimed 并取得 token。被认领对象禁止新增 pin、引用或写入该 generation；新上传使用新 generation 或等待本次清理结束。

GC 在事务外只删除自己持有的确切 generation 路径，再以当前 token 登记 deleted。租约过期的旧 GC 即使迟到执行 unlink，也不能删除新 generation 的原件。长写入只发生在 attempt 暂存；失效 reservation 的晚到上传不能安装到 gc_claimed/deleted generation，更不能登记成功。最终安装与状态/引用登记在同一短写锁区间协调，且只能执行已校验同卷文件的短原子操作，不在锁内复制、散列或转换。安装后 DB 提交失败的字节仍是未登记孤儿，由原 generation 状态清理。重试删除须保持幂等；Windows 文件占用等失败保留 gc_claimed 与诊断，不能假报完成。下载/备份若需要无业务引用对象，须同样 pin；正常已登记版本由持久引用保护。

验证两个真实连接交错顺序：上传 pin/登记先赢则 GC 不得认领；GC 先赢则原 generation 登记失败并安全重新上传。另注入旧 GC 迟到 unlink，确认新 generation 文件与下载哈希不受影响；以及 GC 已记 deleted 后旧上传晚到，确认它只能留下可清理的 attempt 暂存，不能重新安装 original。单纯“删除前再查一次引用”不能通过此验收。本节是待 T05 实现的合同，当前骨架未实现对象库。
