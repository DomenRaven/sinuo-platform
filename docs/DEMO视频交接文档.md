# 思诺（Seno）Demo 视频制作交接文档

> 本文档写给负责制作演示视频的 DeepSeek Harness。
> 目标：在不看任何历史对话的前提下，仅凭本文档即可**理解项目、启动服务、走通一条完整演示路径、并产出视频脚本**。
> 文档内所有账号、URL、项目 ID、操作步骤、截图路径均为**当前真实值**，可直接照用。

## 0. 一句话定位

**思诺（Seno）是一个面向工业设计课程项目的「AI 辅助设计与过程管理平台」。**

学生（设计师）用「书—章—页—节点」的层级保存自己的设计过程；四个智能体分工做**查证据、选方法、检查过程、提议下一步**；但**所有决定与确认权始终在人手里**。

> 它**不是**训练平台，**不是** CAD / Figma 的替代品，**不做** 3D 建模。它做的事是：把设计过程中「为什么要这么做、依据是什么、试过哪些、怎么决定的」这条推理链，结构化和可回溯地记录下来，并让 AI 在每一步帮你查证、把关、建议。

## 1. 核心概念（必须先理解）

### 1.1 层级：书 → 章 → 页 → 节点 → 版本

| 层级 | 含义 | 类比 |
|---|---|---|
| **书** | 一个设计项目（Project） | 一本「项目书」 |
| **章** | 一个设计阶段（Stage），固定 8 个 | 书的章节 |
| **页** | 阶段下的一个具体议题/页面（Page） | 章下的一页 |
| **节点** | 页内的一条推理记录（Node），共 7 类 | 页内的一行笔记/结论 |
| **边** | 节点之间的关系（Edge），共 4 类 | 节点之间的连线 |
| **版本** | 每一次「固化/确认」产生的快照（Version） | 页的历史版本 |

### 1.2 八阶段（章，固定模板，不可改）

1. 任务与情境
2. 用户与场景研究
3. 问题及机会定义
4. 设计要求
5. 概念探索
6. 深化与原型
7. 测试与迭代
8. 表达与复盘

> 同一阶段可以有**平行页**（多个并列议题），系统**不会**自动把平行页连成前后顺序。

### 1.3 七类节点（当前已开放）

**问题、证据、洞察、要求、作品、测试、决定**。

- 每个节点可带一段**正文内容**。
- 颜色对应产出它的角色（见 1.5）。
- `作品 / 测试 / 决定` 三类由**人**确认（是人做的事）；其余由智能体产出或人记录。

> 说明：白皮书对象模型里还有「素材」「概念」两类，**当前未开放**（未进入 2026-11-01 的范围决定与 WAVE_F03 合同）。演示时如被问到，按此口径回答即可，不必多解释。

### 1.4 四类关系边（节点之间的连线）

| kind | 标签 | 含义 |
|---|---|---|
| `derives` | 承接 | 目标承接自源（源是它的依据） |
| `supports` | 支持 | 源支持目标 |
| `refutes` | 反例 | 源与目标矛盾 |
| `cites` | 引用 | 源引用目标 |

### 1.5 四类智能体（一次运行最多三个职责）

| 职责 | 英文 role | 做什么 | 产出 |
|---|---|---|---|
| **课题澄清** | clarification | 澄清任务目标、汇总简报 | summary / 简报 |
| **证据查找** | evidence | 查证据、给依据 | 证据命中片段 + 缺口 |
| **方法建议** | method | 匹配方法卡 | 方法建议 |
| **过程检查** | critic | 读节点与阶段表、判断能否进入下一阶段、提议新节点或关系边 | 结论 + 缺口 + 候选 |

### 1.6 意图分流（用户说什么 → 触发谁）

| 用户输入 | 触发职责 |
|---|---|
| `查证据` / `问资料` / `找依据` | 证据查找 |
| `选方法` / `问方法` | 方法建议 |
| `检查下一步` / `下一步` | 证据查找 + 过程检查 |
| `简报变化` | 课题澄清 |

### 1.7 关键规则（演示时要讲清楚的核心机制）

1. **写节点只改草稿，不产生版本**。必须先「确认为正式版本」（固化/checkpoint），页面才真正变化。
2. **候选必须预览再确认**。智能体的提议（新节点、关系边、建新页）一律先变成「待确认」候选卡，人点了「预览 → 确认/拒绝」才生效。
3. **确认权在人**：`作品 / 测试 / 决定` 节点只能由人写入；智能体只提议，不能越权提交。
4. **证据要可回溯**：每条证据都锚定到上传的原件（页码/区间），结论能点回出处。

## 2. 系统形态（一句话了解技术面）

- **后端**：Python FastAPI + SQLite，自研 asyncio DAG runner 驱动多智能体协同；`src/sinuo/`。
- **前端**：单文件 SPA `web/desk.html`（约 2500 行，苹果式视觉：淡鹅黄背景 `#f7f1dd`、圆角大卡片、蓝色章泳道）。
- **大模型**：真实 DeepSeek（`SINUO_MODEL_NAME` 负责澄清/证据，`SINUO_MODEL_NAME_REASONING` 负责方法/过程检查）。另有一套假模型链仅用于逻辑测试。
- **检索**：SQLite trigram 全文索引做证据检索；字符 n-gram（阈值 0.12）做理论库/方法库检索。
- **数据**：`var/sinuo.db`（SQLite，44 张业务表 + 检索索引影子表）；理论库 `var/theory/`。

## 3. 三屏界面与功能清单

前端挂在 4 个路由，核心是三屏：

| 路由 | 界面 | 功能 |
|---|---|---|
| `/projects` | **项目书架** | 登录、项目列表、智能体能力卡、新建项目 |
| `/projects/{项目id}` | **项目地图** | 章页画布：8 章泳道、页缩略图、跨章承接连线、页拖拽重排 |
| `/projects/{项目id}/pages/{页id}` | **单页工作台** | 左右分区：写节点、页内推理图（链式节点+关系边）、中间交付物、对话、读集勾选、候选确认 |
| `/` | 重定向到书架 | — |

### 3.1 项目书架（`/projects`）
- 顶部导航：思诺 / 项目书架 / 项目地图。
- 展示当前账号的项目卡片；下方有「新建项目」表单。
- 新建项目会**自动写入固定八阶段**。

### 3.2 项目地图（章页画布，`/projects/{id}`）
- **章 = 蓝色渐变色块泳道**，章头显示章名 + 页数。
- **页 = 缩略图卡片**，可点进工作台。
- **跨章承接关系 = 蓝色虚线箭头**（数据来自真实 `page_edges`）。
- **页缩略图可拖拽**：按住卡片底部「⠿ 拖拽」把手，可跨章移动、同章重排；布局存在浏览器本地（`localStorage`）。

### 3.3 单页工作台（`/projects/{id}/pages/{id}`）
左侧「**你的工作**」（人做的事）：
1. **写节点**：选类型（7 类）+ 填正文 → 「记下这个节点」。
2. **页内推理图**：链式节点图（带圆点+竖线），节点卡显示类型/职责/正文/状态；点击可编辑/删除；节点右侧「↗」把手可拖到另一节点**连线**（选承接/支持/反例/引用）。
3. **中间交付物**：上传的作品/草图/测试记录，带版本号。
4. **确认为正式版本**（固化/checkpoint）。

右侧「**智能体工作**」（AI 做的事）：
1. **对话输入框**：自由文本或快捷按钮触发。
2. **本次读取范围**：勾选邻页、作品、是否跳过理论库/方法卡（只影响下一次运行）。
3. **运行轨迹**：本次运行的提问气泡 + 各角色卡（总结/缺口/依据）+ 工具调用链。
4. **待确认候选卡**：智能体的提议，需预览后确认/拒绝。

## 8. 注意事项与口径边界（视频里别踩坑）

1. **确认权在人**：这是产品核心卖点，务必在解说中强调。
2. **不编造数据**：OXO 案例的样本量/通过率/临床数据**一概没有**，也不该有。智能体被设计为「诚实交代边界」。
3. **不做 3D**：不要提 GLB / 3D 模型。
4. **素材/概念节点未开放**：如被问到，说「仍在白皮书对象模型规划中，当前开放七类」即可。
5. **证据检索要带具体关键词**：输入「查证据」这类不带词的话，检索会显示「无结果」；带「细硬金属柄」这类具体词才会命中。演示「查证据命中」时，对话里要带上具体关键词。
6. **两个同名 OXO 项目**：务必用 `faf5436c`，不要用 `bd130115`。
7. **缩略图/拖拽**：章页画布的页拖拽布局存在浏览器本地，换浏览器/清缓存会重置——这不影响演示，但别当成「已持久化到服务端」来讲。
