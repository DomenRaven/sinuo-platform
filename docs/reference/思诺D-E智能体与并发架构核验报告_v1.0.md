# 思诺 D/E 智能体与并发架构核验报告

**版本：1.0｜2026 年 10 月 29 日**  
**范围：** D 版 `edu-src-20261009-020001/edu-platform`、E 版三个代码快照、已锁定产品白皮书 2.1、技术实施规范 1.1、UI 页面实施规范 1.1、UI 白皮书 1.3。  
**证据等级：** 代码与文档静态核验；未启动 D/E 服务，未调用 DeepSeek，未做并发压测。密钥文件未打开。

## 1 结论

现定的四类智能体职责能支撑首版纵向任务链。任务澄清处理简报，证据能力负责来源与反例，方法能力匹配适用条件，过程批评负责对照要求、作品和测试，并给出下一步建议。概念生成、测试方案细化、报告表达可以作为后续能力；文件解析、权限、编排、存储和确认提交应由系统组件承担。这样既体现智能体分工，也避免把每个服务或提示词都命名为智能体。

现有实施合同的主要缺口是多任务并发时的结果隔离、跨请求状态、撤权后的流事件、同一页多人编辑，以及原件与业务版本的统一恢复。本轮已在技术实施规范 1.1 中补齐执行依赖图、单运行快照、独立输出槽、CAS、Outbox、重试与故障用例；在 UI 页面规范 1.1 中补齐并行运行、部分失败和撤权的可见状态。这些仍是**待实现合同**，不能当作已经通过的系统测试。

## 3 工作流、并发读写与通信核验

用户所说的“多模块同时工作并读写”，包含六个工程问题：谁先做、哪些任务可以并行、各任务看到哪个版本、谁有写入权、消息失败后怎么重试，以及断线或撤权后如何保持一致。技术实施规范第 14 节已经将其定义为可测试合同。

| 核验项 | D/E 静态证据 | 思诺实施判定 |
| --- | --- | --- |
| 并行结果合并 | D `aiJobs.js:79-100` 的检查后建任务并非原子；`aiJobsWorker.js:14-39` 二次读 revision 后整文档写入。E 截止版 `core_state.py:19-28` 字典 reducer 浅合并，同键仍后写覆盖 | 一个 `AgentRun` 固定输入；每个 `task_id` 写独立结果槽；依赖图决定并行或等待；领域写由 CAS 与数据库事务保护 |
| 阶段推进 | E 截止版 `research_orchestration_agent.py:714-739,1187-1221` 会自动推进并写决策点 | 阶段建议仅是 `Candidate`；具权者预览并确认后才建下一章空白页 |
| 跨请求状态 | E 截止版 `api_server.py:944-961` 每次新建 state，缺少阶段历史；编排器 `:1397-1400` 可回落初始阶段 | 当前章、页、正式版本均从领域库精确读取；AI checkpoint 只用于运行恢复 |
| 流事件授权 | E 基础版 `api_server.py:172-180,714-767` 信任自报身份；截止版虽有 Bearer 校验，但 `:250,313-326,752-818` 仍按 `session_id` 向队列广播 | 订阅绑定租户/项目/运行/主体；连接、回放和撤权时重校权限；消息只带安全引用 |
| 记忆与版本 | E 截止版 `memory_versioning.py:246-313,388-432` 的时间旅行会改 `current_node_id`；D `aiInitStore.ts:10-67` 的运行历史仅在 localStorage | 历史查看为只读 GET；新分支走新页命令；业务真相是数据库与原件库，运行轨迹持久化 |
| 覆盖与删除 | D `aiJobsWorker.js:81-105` 局部持久化会先删该课程树上的旧概念；`sqlKv.js:105-130` 单 key upsert 无实体 CAS | 不覆盖旧页、旧原件与旧决定；草稿可变，确认版本和作品版本不可变 |
| 消息确认 | E 截止版 `memory_communication.py:231-247,339-351` 存在先入队、后登记 ACK 的竞态；`memory_models.py:662-685` 信封缺项目/对象/版本/权限范围 | 业务 Outbox 同事务落库；消费者幂等；信封包含范围与版本；不把投递成功视为业务写成功 |

**并发的合理上限。** 单机演示可以用 SQLite WAL、短事务和一个串行写队列；读与模型任务可以并行。该配置只说明正确性路径，吞吐能力还需实测。多人团队部署前需测 C01–C06；若写冲突和等待不可接受，再迁 PostgreSQL。进程内锁不能替代条件更新、唯一约束和事务。

## 4 权限、模型访问与存储

**权限。** 发起者的授权读集在服务端生成，模型只能调用受限只读工具。权限快照用于重演“当时看到了什么”，不保证用户之后仍有读取权；后续工具、SSE 重连和候选确认按当前 ACL 再查。设计负责人、团队成员、资方和上下游的角色标签只给默认范围，对象和字段敏感级别继续裁剪。下载、缩略图、搜索片段、导出及日志都必须使用同一授权规则。

**DeepSeek。** D 版 `server/src/lib/deepseek.js:1-13` 已有调用适配的雏形，但 `teacher/src/data/aiConfig.ts:20-78` 可将 API key 放进浏览器 localStorage，`aiClient.ts:91-112` 可从前端经请求头或直连发送；不适合作为思诺的接入方案。新版本仅由服务端持有密钥，浏览器只调用本项目 API。目标目录 `D:\AAA学习\大三上\设计大数据基础\大作业` 中存在密钥文本，本轮未读取。模型名和价格按部署当日官方文档验证。模型输出先做本地 Schema、锚点、版本和权限校验，再发布候选。

**存储。** D 版 `store.js:9-23`、`sqlKv.js:20-30,105-130` 是 SQLite KV；课程库接口 `courses.js:553-585` 有 `baseRevision` 冲突响应，但以整文档覆盖为主，不能承担思诺的页、节点、作品和决定版本。思诺要把原件版本、页版本、谱系边、决定、运行轨迹、审计与 Outbox 分开建模，并提供同一项目时间点的可重建读投影。预览、OCR、索引是可重建派生物；Figma、PSD、AE、PR、SolidWorks、CAD 等原件先可靠保存、记录格式和版本，可信缩略图/封面按转换能力分级，不承诺每种格式都可解析。

## 5 UI 与人格核验

逐页规范 R01–R15 覆盖项目建立、阶段与平行页、单页工作、历史、资源、搜索、AI 运行、读集、审阅、导出和设置。密度风险集中在 R05、R10、R11：同时放图、对象抽屉、运行轨迹与记忆图，会挤压证据阅读。修订后 R05 以画布/列表为主体，右栏互斥；R10 给任务、结果、来源和确认一个完整页面；R11 默认列表，图为辅助；R06 区分历史只读与创建新路线。事务对话框显示将创建的对象和来源，聊天气泡仅承载短问答，重要输出用卡片。

第二周 Iris 人格材料可复用“先观察任务、依据材料、建议有分寸”。艺廊、音乐和固定金句属于原产品设定；重复“不是……而是……”及“必须由你亲手……”会让设计助手像在表演边界。本轮《思诺基础人格与智能体语言规范》改用自然、具体的任务语言。该规范不能代替服务端权限与事实校验；语气效果还需要真实 DeepSeek 输出的人评题集。

## 6 结论等级与下一步验证

| 维度 | 当前评价 | 证据缺口 |
| --- | --- | --- |
| 智能体职能 | 首版任务链完整，四职责加编排/校验/服务层的划分合理 | 任务分类正确率和不同职责真实收益未测 |

建议先在隔离的 D 项目开发副本实现一个纵向切片：上传一个资料版本→生成可定位证据→运行证据与过程检查→人工确认新页→回看历史并创建分支。用同一课题执行技术 C01–C06、UI T01–T14 和人格题集，再决定是否引入更多智能体或复杂消息基础设施。
