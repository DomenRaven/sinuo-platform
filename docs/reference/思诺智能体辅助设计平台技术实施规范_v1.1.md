## 0 决策摘要与适用范围

思诺首版需要跑通一条可复核的工业设计任务链：资料进入项目，设计师从准确的原件版本提取证据，智能体按任务选择专责能力提出有依据的候选，具项目决策权限的人确认后形成设计要求、下一阶段空白页或新的探索分支。所有重要关系回到确切版本，审阅者只在授权范围内查看。实现优先级以锁定产品稿的 F01–F24 为准；本规范把其中未定的工程细节落成接口与不变量，不提升 P1/P2 功能为首版承诺。

以下四个决定贯穿所有服务和 UI：

1. **业务真相由领域数据库和原件存储共同承担。** AI checkpoint、对话、摘要、检索索引、缩略图都不能代替 `PageVersion`、`ArtifactVersion`、`Decision` 与审计账本。
2. **自动保存草稿与确认版本是两条状态线。** AI 可读取经授权的草稿，但运行必须绑定 `base_page_version_id + draft_content_revision + draft_content_hash`。画布坐标另用 `draft_layout_revision`，不使设计候选无谓过期。
3. **“翻到下一章”与“从旧版分支”是两种命令。** 前者创建主体空白的新页，承接来源版本和显式选择的引用；后者创建新的页身份，并以旧版内容为可编辑起点，保留原页和旧测试，不把旧决定或测试伪装成新确认结果。
4. **模型只读业务域，只写运行域。** 智能体能选择获授权的只读工具、输出候选和运行记录；具权者查看差异并确认后，领域命令服务再做权限、证据、版本和幂等校验，才写入业务对象。

**术语约定。** `Stage` 是项目内的章；`Page` 是一张平行探索页的稳定身份；`PageDraft` 是可变工作态；`PageVersion` 是不可变确认快照；`PageEdge` 是确切版本之间的承接或分支关系。用户看到的树状图是有类型关系图的布局，不是数据库只存一个 `parent_id`。`ContextSnapshot` 是某一次 AI 运行的授权读集，不是“项目的唯一当前记忆”。

**已知与待验证。** D 盘教育平台和 E 盘早期主干只经局部或静态核查，不能据此断言可直接移植。P0 后端栈已按施工规范 01 冻结为 Python、FastAPI、同步 SQLAlchemy、SQLite WAL、Alembic 与服务端 HTTPX 适配；前端留待 UI 阶段。端点与事件以施工规范 04 为公开合同，运行三状态机以 05 为准，存储与认证以 06 为准。预算阈值仍是待实测的配置起点。课程第 15 讲作为参考基线，不冒充正式评分规则。

**部署取向。** 单机课程演示可用一个 Web 进程、一个 API/AI 进程、一个 Worker、SQLite（WAL、FK、`busy_timeout`、串行写）和项目隔离的本地对象目录。团队并发先以真实运行基线验证，再考虑 PostgreSQL 与 S3 兼容对象存储；不因“多智能体”名字立即引入 Redis、Kafka 或微服务。旧 D/E 组件只作源码参考；P0 后端采用已冻结栈，LangGraph 或其他基础设施变更须先写 ADR 并通过等价验收，不默认搬旧编排与权限系统。

## 2 技术 BOM 与引入门槛

BOM 是**需要建造和核验的能力清单**，不是已采购或已运行软件清单。版本、许可证、模型价格与可用性在实施基线阶段登记；本稿不填写未经实测的费用或性能。

| 项目 | P0 数量/候选 | 输入与输出 | 采购或集成门槛 | P1/P2 边界 |
| --- | --- | --- | --- | --- |
| 浏览器前端 | 1 个 Web 应用；候选 Next.js/React | 稳定路由、图/列表同 ID、可访问的候选与审阅 UI | 先验证 E/D 前端构建；图控件的许可、键盘和大图性能要测 | P2 实时共编 |
| 领域 API | 1 个模块化服务；FastAPI + Pydantic/OpenAPI | 业务读投影、事务命令、授权与错误码 | 旧 E API 的医疗语义及 SSE 末事件合同需重写或核验 | 团队化后再拆服务 |
| 关系库 | P0 SQLite 1 库，完整迁移脚本 | 页版本、谱系、权限、候选状态、审计、Outbox | 必测 FK、CAS、幂等、备份恢复；不能外推并发性能 | 团队部署 PostgreSQL |
| 原件库 | 项目隔离的内容寻址目录 1 套 | 不可覆盖原件、SHA-256、短时授权下载 | 大文件限额、隔离暂存、备份和合法删除政策 | S3 兼容对象库 |
| 派生 Worker | 1 个持久任务消费者 | 图片/PDF/至少一种 3D 预览、抽取状态 | 工具许可证、格式容错与恶意文件隔离要查 | 更多专业格式自动预览 |
| 检索 | 权限过滤 + 关键词索引；向量召回按效果增配 | 带定位的片段、索引版本、已查范围 | 中文检索与锚点正确率实测；索引可重建 | 高规模向量库/GraphRAG |
| 智能体编排 | 1 个代码调度器、4 个按需专责能力、1 个校验层；同一运行按依赖选择 1–3 项 | `TaskInput`→独立 `AgentResult`→`Candidate` | LangGraph 可用于执行 checkpoint，但先验证 E 图的状态合并与异步行为 | 扩展专责能力，不常驻八角色 |
| 模型适配器 | 1 个可替换接口，结构化输出 | 有预算的生成、错误与用量 | 外发资料、保留期、许可、价格必须在部署前决策 | 本地模型/多提供方 |

| 评估与日志 | 1 套固定题集、运行账本、人工量规 | 真实工具日志、引文、费用、失败与修订 | 开发题和最终题分开；不能只用模型自评 | 自动回归与多项目统计 |

**成本记录口径。** 每个 `run_id` 记模型输入/输出 token、模型单价版本、工具调用次数、耗时、预览/抽取任务耗时；报告按请求和任务链汇总。存储分原件字节、派生字节、索引字节；跨页引用不复制原件。任何“节约记忆容量”的说法须分别测上下文 token 与磁盘字节。

## 3 领域对象与版本不变量

| 对象 | 必需字段与关系 | 不可变/更新规则 | UI 身份 |
| --- | --- | --- | --- |
| `Project` | `project_id`、目标、成员、ACL 策略、模板版本 | 设置变更有审计 | 一本项目书 |
| `ProjectRevision` | 项目 ID、递增提交序号、时间、提交命令 ID | 每个业务事务只增一次；可按序号重建当时项目视图 | 项目时间点 |
| `Stage`/`StageConfigVersion` | `stage_id`、项目、活动类型、顺序、目标、模板来源与配置版 | 配置变更追加新版本；不改历史页归属 | 章及章配置历史 |
| `Page` | `page_id`、所属章、标题、负责人、状态、`head_page_version_id` | 身份稳定；头指针 CAS 更新 | 平行探索页 |
| `PageDraft` | `page_id`、`base_page_version_id`、`draft_content_revision`、`draft_content_hash`、`draft_layout_revision`、编辑内容 | 自动保存；内容与布局分别修订 | “草稿 Rn” |
| `PageVersion` | `page_version_id`、页 ID、序号、父版本、冻结节点/边/作品引用、哈希、作者、时间 | 只增不改；历史按 ID 精确读取 | “已确认第 n 版” |
| `Node`/`TypedEdge` | 页内稳定 ID、类型、内容、状态、来源锚点；边端点/方向/类型 | 内容随草稿变化；正式版冻结 | 页内图与列表 |
| `PageEdge` | 源/目标 `page_version_id`、类型、依据、作者、时间 | 谱系边只增；端点不能浮动到最新版 | 章间路径/分支谱系 |
| `Artifact`/`ArtifactVersion` | 逻辑文件 ID、版本 ID、SHA-256、大小、MIME、许可、敏感级别、对象键 | 原件字节不可覆盖；同名新内容新版本 | 资源卡与作品版本 |
| `EvidenceAnchor` | 原件版本、页码/时码/区域、片段、抽取器版本、敏感级别 | 原件定位固定；OCR 修正另存派生版 | 可打开的来源 |
| `Decision`/`TestRecord` | 责任人、理由/准则、候选、测试条件、确切作品版本 | 更正追加新记录并指向旧记录 | 决策与测试卡 |
| `Candidate`/`AgentRun` | 输入快照、来源集合、模型/提示/索引版本、状态、有效期、处置 | 运行域追加；不能代替业务决定 | AI 候选/轨迹 |
| `ContextSnapshot` | 运行读集、权限快照、源版本集合哈希、排除项 | 每次运行固定；切换分支另建 | “本次读取范围” |
| `AuditEvent`/`OutboxEvent`/`IdempotencyRecord` | 操作者、命令、前后版本、请求 ID、时间和结果 | 追加；与业务提交同事务 | 审计/后台任务 |

**三张图不能混用。** 页内主树可有一条阅读主干，辅助的 `supports/contradicts/tests/references` 边属于语义图。页间的 `advances_from/branches_from/merges_from/returns_to` 属谱系 DAG，只允许较早创建的版本指向新版本；阶段顺序可以回退。页面版本祖先链记录同页 v1→v2；跨页来源边只指确切版本。图的布局坐标和筛选属于视图状态，不能生成业务决定。

**章、页、节点的同一时间点。** 每次已确认领域提交写一个递增的 `project_revision`，新页版本、章配置、页边和决定都标记其生效序号；草稿自动保存只更新 `draft_content_revision` 或 `draft_layout_revision`，不进入章历史时间轴。章历史视图由 `StageConfigVersion` 加“该序号时已存在的页及其当时 HEAD”组成，不复制一整章原件；页历史读取确切 `PageVersion`；节点历史是同一 `node_id` 在各页快照中的投影。UI 选择“查看项目第 R 次提交时的用户研究章”是只读查询，返回一个 `StageViewSnapshot`（章配置版、页版本 ID 集和边 ID 集）。它不更改当前章、当前页或其他人的视图。节点在某版尚未出现或后来移除时显示状态，不用最新节点内容回填旧版。历史只重建当时业务状态，读取仍按**查询时的当前权限与隐私墓碑**裁剪，不用旧权限复活已撤权原件、标题、缩略图或数量。

**基础约束。** 数据库至少对外键、`UNIQUE(page_id, version_no)`、`UNIQUE(artifact_id, version_no)`、幂等键和不可变版本的更新/删除禁令给出约束；服务层补跨项目引用、对象级 ACL、边类型、谱系无环与证据锚点校验。`PageVersion` 保存引用的确切 `ArtifactVersion` 清单，不复制原件字节。普通删除草稿节点只影响下一版本；合法隐私删除另走撤权、墓碑和清理流程。

## 4 版本、分支、回溯与记忆的读写合同

### 4.1 五种操作不能共用一个“恢复”按钮

| 用户动作 | 读集与入口 | 写入结果 | 历史与失败处理 |
| --- | --- | --- | --- |
| 在当前页编辑 | 当前 `PageDraft`、其基底页版本；页工作区 | `draft_content_revision` 递增；画布拖动只增 `draft_layout_revision` | `expected_draft_content_revision` 冲突返回 409，保留本地编辑供比较 |
| 确认当前页版本 | 草稿内容、作品引用、当前 HEAD；“保存为版本” | 同一 `Page` 的不可变 vN+1、CAS 头指针、`project_revision` 与审计 | 失败整体回滚；旧 vN 不变 |
| 查看章/页/节点历史 | 指定 `project_revision`、`page_version_id`、`node_id`；版本选择器 | **零业务写入**，仅个人浏览位置变化 | 历史只读，不能以“恢复”覆盖当前 HEAD |
| 从历史版创建分支 | 旧 `PageVersion`；历史面板“从此版创建新路线” | **新 `Page` + v1 分支基线**；复制可编辑的节点/关系内容并分配新 ID，记录 `origin_node_id`/`origin_edge_id`；原件/证据只引用确切旧版本 | 旧 Page 的 HEAD、测试、意见和之后路线完全保留；旧决定/测试只作为历史依据，不重签或继承“通过” |
| 确认进入下一阶段 | 已校验候选与一或多张来源 `PageVersion`；变更预览 | **主体空白**目标页 v1、来源边、被人显式选择的引用、`Decision` 与审计 | 拒绝只写候选处置；冲突不建半张页 |

分支默认留在源版所属章，选择其他章时 UI 必须说明新章的目标和承接关系。从旧版复制的是**设计工作起点**，不是把旧决定和旧测试重新确认：新页的候选节点标明来源版本，测试记录仍指原作品版本并显示“历史测试，需复核”。合流与回访也创建时间上更新的新页并保存全部来源版本，谱系仍无环。

**流畅切换的读模型。** 章快照、页快照和节点详情均以确切版本 ID 作查询键；客户端可在当前授权下预取相邻一层页和相邻页版本的安全读投影，返回带 `ETag` 与权限纪元。图布局、缩放、筛选和焦点按“用户 + 页版本 + 视图”保存为个人视图状态，切换后恢复，不能写回业务图。正在加载旧版时保留清晰的目标版本骨架，不把新标题配旧节点或把旧缩略图配新权限。权限纪元变化或撤权时立即清除相关内存与浏览器缓存，并重新授权预览和原件 URL；受限原文不进入可离线持久缓存。预取只改善浏览，绝不预提交版本、分支或候选。

### 4.2 草稿与候选的双版本门槛

一次 AI 运行有 `input_mode = confirmed | draft_preview | historical_readonly`。`confirmed` 读取确切页版本；`draft_preview` 读取该版上的自动保存草稿，额外固定 `draft_content_revision` 和 `draft_content_hash`；`historical_readonly` 可解释旧状态，但其候选不能提交到旧快照。任何模式都绑定 `permission_snapshot_id`、所用证据/作品版本、索引版本与 `context_source_set_hash`。同一页只移动节点位置时 `draft_layout_revision` 改变，不使内容候选过期；节点内容、类型、逻辑边或作品引用变化时 `draft_content_revision` 改变，旧候选变过期。权限撤销、来源失效、方法卡或索引变化时，根据受影响引用重新校验，不把旧摘要当最新事实。

`draft_preview` 产出的普通便签候选可在具权者确认后写入当前草稿，并保留 AI 原稿和人工修改；设计要求确认、分支、合流和阶段推进属于关键动作，提交时须在同一事务中先冻结必要草稿为正式版本，再写目标对象，或要求用户先显式“保存为版本并重新检查”。P0 推荐后一种更容易验证的流程：变更预览会指出哪些草稿未定稿，并给出“保存为版本→重新检查”连续操作。不能只比较 `page_version_id` 就放行基于旧草稿的建议。

### 4.3 事务、幂等与孤儿处理

所有业务修改命令必须带 `Idempotency-Key`；`request_id` 仅作追踪与回执关联，不能代替幂等键。登录、登出等身份生命周期按安全合同例外处理；唯一键为“项目 + 操作者 + 命令 + 请求键”。同键同请求体返回首次结果，同键不同请求体返回 409。当前页快照同时校验 `expected_head_page_version_id` 与 `expected_draft_content_revision`；多来源建页逐一检查来源版本与访问权。每个成功的已确认领域事务写 `AuditEvent`、递增 `ProjectRevision`、写 `OutboxEvent` 和幂等结果，随后提交。草稿自动保存也需幂等、修订冲突检查和必要审计，但不创建正式 `PageVersion` 或递增项目时间轴；派生 Worker 的状态变更用自己的任务修订，不伪装为设计决定。SSE 中断后客户端用请求键查结果，不再盲目重发新键。

原件上传走隔离暂存：申请上传票据→传字节→服务端重新计算哈希、大小和类型→持久化不可变原件→事务登记 `ArtifactVersion` 与 Outbox。长写入只进 attempt 暂存；最终安装与引用登记按对象 generation、reservation/pin、state/fence 的短锁协议协调。清理先 CAS 认领无有效引用且无有效 pin 的确切 generation，旧 GC 不能删除新 generation。数据库失败的孤儿与迟到上传按施工规范 06 清理，不能只按文件年龄判断，不能清理已有登记原件。Worker 以 `artifact_version_id + generator_version` 作为任务键生成预览、OCR 和索引；失败只更新派生状态，原件仍可下载。原件已保存、预览已生成、可检索、已关联为证据是四个不同状态，UI 逐项表示。

### 4.4 记忆读集切换

一次运行固定一份 `ContextSnapshot`：当前页版本与可选草稿修订、获授权邻页版本、证据锚点、作品版本、方法卡版本、索引修订、权限快照、排除项和摘要来源哈希。设计师从 A 路线切到 B 路线时，只改变**自己的浏览/下一次运行读集**，不修改全项目“当前分支”。A 的运行轨迹和候选仍可按当时输入查看，但不能自动带入 B；B 要产生新的 `run_id`。用户勾选或排除摘要只改变新运行的读取范围，不删除已确认事实。若要纠正事实，必须在相应页形成新修订，并让旧记录可回溯。

四层记忆分别是原件与会话归档、已确认项目事实、绑定来源版本的可重建摘要/索引、单次运行短上下文。检索先在服务端过滤 ACL，再召回，再复核锚点与版本。历史摘要可显示“依据当时版本生成”，但不能自动进入当前默认检索；撤权内容也不能通过摘要、预览、SSE、日志或浏览器缓存旁路泄露。性能优化通过有界图邻域与相关性读取实现，是否减少 token 需实际测量。

### 4.5 合法删除与恢复

普通放弃、合流和回溯不删除历史。受访者撤回授权或有权者执行隐私删除时，先撤销访问并使候选、索引、摘要失效，随后以审计墓碑替代敏感引用，清除原件/派生件并按部署政策处理备份。历史页可显示“当时曾引用，现已失效”，不能显示原文或自动改绑另一个文件。备份需同时覆盖关系库快照、原件清单和哈希；恢复演练应重建一条含页分支、证据锚点、作品版本和权限的链。RPO/RTO 在演练后设定，不在此稿凭空承诺。

## 5 主体权限与功能点

权限由角色、项目成员、对象 ACL、字段敏感级别和动作共同计算；任何名称本身都不授予原始访谈、保密工程件、缩略图或日志全文的读取权。以下矩阵表示默认能力，具体项目可收紧；关键决定需单独 `decision.confirm`。

| 主体 | 默认可读 | 可写/写出 | 必须拒绝或另授权 |
| --- | --- | --- | --- |
| 主设计师 | 已分配页、授权证据、作品、候选与轨迹 | 草稿、快照、上传、自己的意见；获授 `decision.confirm` 后提交关键决定 | 其他项目和被单独限制的敏感原件 |
| 团队成员 | 分配页与共享资料 | 分配页草稿、版本/分支按授权；P1 评论交接 | 默认不能代表项目确认阶段、改他人意见 |
| 设计负责人或总监 | 共享路径、授权证据与作品版本 | 独立审阅意见；获授决策权后确认 | 默认不能改写设计师草稿或跨对象敏感资料 |
| 资方与项目评审 | 授权里程碑与共享证据摘要 | 自己的审阅意见 | 默认无原始访谈、保密工程件及其缩略图 |
| 上下游专业团队 | 获共享作品版本与约束 | 专业意见；正式要求仍由具权者确认 | 默认不能改项目要求、历史版本或其他团队资料 |
| AI 运行主体 | 发起者权限裁剪后的快照与只读工具结果 | 运行域的 `AgentRun`、候选、可重建摘要 | 不能 `page.checkpoint`、`decision.confirm`、`artifact.delete`、`acl.manage`；不能直连业务写库 |
| 派生 Worker | 任务指定原件版本 | 相应预览、抽取、索引状态 | 不能修改原件、页版本或决定 |
| 隐私处理具权者 | 删除请求涉及的范围 | 撤权、墓碑、清理任务与审计 | 不能用普通放弃分支代替合法删除 |

建议冻结动作枚举：`project.read`、`stage.configure`、`page.read`、`page.draft.write`、`page.checkpoint`、`page.branch`、`decision.confirm`、`artifact.upload`、`artifact.original.read`、`preview.read`、`evidence.read`、`opinion.create`、`opinion.edit_own`、`report.export`、`acl.manage`、`privacy.delete`。原件与预览经服务端按当前权限代理下载，不签发能绕过后续撤权的对象直连链接，也不返回磁盘路径。前端禁用按钮仅帮助理解，服务器仍须逐条拒绝越权请求。

## 6 智能体与组成部分的逐项合同

四个 P0 专责能力是按任务调用的**逻辑职责**，可共享一个模型与适配器；不要求部署四个模型。一次运行按依赖调用必要的 1–3 个专责能力。任务澄清、找证据、问方法、检查下一步走不同路径；未调用的职责不产生虚构的发言或费用。概念发散、工程结论、全程八角色和自动评分仍受产品稿 P1/P2 边界约束。

| 组成部分 | 触发与处理步骤 | 允许读取 | 可写运行域/写出 | 禁止动作与失败结果 |
| --- | --- | --- | --- | --- |
| 领域入口与授权层 | 认证→项目/对象/字段授权→限额→生成权限快照 | 成员、对象 ACL、当前业务状态 | 安全访问事件、运行启动响应 | 不接受客户端自报角色或工具清单 |
| 代码调度器 | 意图分类、风险判别、规则先检、选择 1–3 个职责、预算/停止条件 | 用户意图、冻结读集、工具目录、模板 | `RunPlan`、状态事件、checkpoint | 不把 `planned` 包装成独立 LLM 角色；不能发业务写命令 |
| 上下文装配器 | 裁剪邻页与证据，加入来源版本、排除项和预算 | 已授权页/草稿/方法卡、摘要和索引 | `ContextSnapshot`、来源集合哈希 | 不带入其他分支或无权摘要 |
| 任务澄清智能体 | 简报创建或变化；列目标、约束冲突与待问问题 | 简报版本、项目约束、阶段模板 | `BriefClarification` 候选、定位与未知项 | 不把猜测当已确认任务 |
| 证据智能体 | 溯源问题/要求；找支持、反例、冲突与无命中范围 | 有权片段、作品元数据、有限图邻域 | `EvidenceBundle`、`claims[]` 与锚点/缺口 | 不编造原话、页码、时码或区域；无命中返回已查范围 |
| 方法智能体 | 按设计问题、资料和资源条件建议方法 | 有许可的方法卡、项目阶段、样本条件 | `MethodProposal`：适用条件、步骤、输入、产物、误用和来源 | 不仅凭阶段名称强推方法 |
| 过程批评智能体 | 规则检查后核对要求、证据、作品与测试关系 | 当前输入快照、证据结果、规则输出 | `StageSuggestion`：继续/推进/回访及理由、缺口、有效期 | 不自动翻页、宣称设计质量或继承旧测试 |
| 只读工具网关 | 参数 Schema、项目范围、返回上限、超时、脱敏与追踪 | 仅服务端计算的授权对象 | `ToolResult`、安全日志与可重试错误 | 不让模型传 SQL、任意路径、URL 或领域写命令 |
| 合成/校验层 | 保留分歧；检查 Schema、锚点、权限、版本、禁止动作 | 各职责独立命名空间结果、原始工具证据 | 已校验候选或失败原因，才可发 `candidate.ready` | 不用模型“投票”掩盖来源矛盾 |
| 候选与运行账本 | 保存原建议、人工修订、拒绝、过期和确认链 | 运行、候选、处置 | 运行域追加记录 | 不成为确认事实的唯一来源 |
| 领域命令服务 | 具权者确认后重新校验并原子提交 | 最新业务 HEAD、草稿修订、候选、ACL 与来源 | 页/版本/边/决定/审计/Outbox | 模型和 SSE 不能直接调用 |

工具合同要有输入/输出 Schema、项目范围、最大返回量、超时、错误码和审计字段。P0 建议提供以下五个只读工具；第六项 `commit_candidate` 只属于领域应用命令，不列入模型可调用工具：

| 工具 | 受限输入 | 必需输出 | 失败退路 |
| --- | --- | --- | --- |
| `search_evidence` | `query`、授权 `scope_ids`、白名单过滤、`limit<=12` | 片段、锚点、原件版本、页码/时码/区域、索引版本、已查范围 | 空集/索引待处理明确标示；不补造来源 |
| `get_page_snapshot` | 确切 `page_version_id` 或有权限的草稿快照 ID | 节点、边、作品引用、哈希和可见性 | 403/404 分开留安全审计，响应不泄露隐藏标题 |
| `get_graph_neighborhood` | 起点、边类型白名单、`depth<=2`、`max_nodes<=30` | 端点版本、有类型边、截断标志 | 超限返回截断而非全图灌入上下文 |
| `lookup_method` | 问题、设计情境、样本/资源约束 | 方法卡版本、来源、输入、步骤、限制 | 无匹配时列缺少的适用条件 |
| `compare_versions` | 同项目两页版本或两作品版本 ID | 结构化差异、测试适用性状态 | 二进制差异不伪装 CAD 语义判断 |

`AgentResult` 必填 `schema_version`、`agent_id`、`run_id`、`input_snapshot_id`、简要结论、`claims[]`（主张、来源锚点、适用范围、证据级别）、`proposals[]`、`gaps[]`、`tool_call_ids[]`、模型/提示版本与降级原因。首版证据级别用“充分/有限/未知”，不是未经校准的设计质量概率。各职责写到独立命名空间，合成层读取并保留分歧，避免同名自由字典覆盖。

**候选动作联合类型。** 允许 `add_node`、`add_typed_edge`、`attach_artifact_version`、`draft_decision`、`suggest_stage_transition`、`create_page_from_versions`。最后一种必须声明 `creation_mode = stage_blank | history_branch | merge_blank`：阶段推进与合流新页主体空白；历史分支从指定旧快照继承可编辑内容，服务端不接受未声明模式。每项带目标对象、写入范围（草稿/正式版本）、来源版本与锚点、预条件、变更预览文案和 `proposed_by_run_id`。人工修改另存 `user_patch`、作者和差异；原建议不可被覆盖。删除历史、提升权限、读取私有资料和自动提交报告不在候选动作类型中。

**运行状态与展示投影。** 页面可展示 received、context_scoped、planned、evidence_retrieved、critic_checked、candidate_ready、await_user 等步骤；这些是事件/读模型标签，不组成单一持久状态机。权威状态分别为 `AgentRun.execution_status = queued/running/completed/partial/failed/cancelled`、`RunTask.status = blocked/queued/running/succeeded/retry_wait/failed/cancelled`、`Candidate.status = pending/committed/rejected/expired`。等待用户由 pending 候选表达，不占模型线程；仅领域命令能提交业务结果。默认预算起点为最多 3 个专责能力、6 次只读工具、12 个片段、图邻域 30 节点/2 跳、总时限 60 秒、单工具临时错误最多重试 1 次；调用、token、费用与重试共享运行级原子预算，未知用量标待核。这些配置不是体验或成本实测结果。

## 7 通信协议、接口和错误语义

### 7.1 客户端与服务端

客户端使用同源 HTTPS + JSON 读写业务对象。AI 运行启动返回 `202 + run_id`，进度采用 `text/event-stream` SSE；理由是首版只有服务端向浏览器单向推送步骤，没有多人实时双向光标需求。浏览器 `EventSource` 如不能附自定义认证头，使用安全同站 Cookie 或短时一次性流令牌；重连仍重新授权。业务提交结果只以领域 API 响应与随后按版本读取为准，不能依赖 SSE 最后一帧。

| 端点/命令 | 输入要点 | 返回与前端动作 |
| --- | --- | --- |
| `GET /api/v1/projects/{p}/stages/{s}?at_project_revision=R` | 项目、章、可选时间点 | 章配置版、当时页版本与页边清单；历史只读 |
| `GET /api/v1/pages/{g}?version_id=...` | 不传版本取当前读投影；传 ID 取确切历史 | HEAD、`draft_content_revision`、`draft_layout_revision`、权限投影、ETag |
| `PATCH /api/v1/pages/{g}/draft` | 类型化操作、`expected_draft_content_revision`、`Idempotency-Key`；`request_id` 追踪 | 新修订或 409 与差异；布局保存使用独立端点/修订 |
| `POST /api/v1/pages/{g}/checkpoints` | 预期 HEAD、预期草稿修订、摘要、请求键 | 新 `PageVersion` 与 `project_revision` 或整体回滚 |
| `POST /api/v1/pages/{g}/branches` | 源版本、目标章、继承内容清单、明确确认、请求键 | 新 Page/v1、`branches_from`、来源映射；原页不变 |
| `POST /api/v1/projects/{p}/agent-runs` | 页/版本、可选草稿修订、意图、选中读集、请求键 | `202 + run_id + events_url`；服务端派生 ACL/预算 |
| `GET /api/v1/agent-runs/{r}/events` | `Last-Event-ID` | 递增事件重放；缺号时拉运行快照 |
| `POST /api/v1/candidates/{c}/preview` | 当前版本/草稿修订、规范化 `user_patch` | 保存服务器预览，返回 `preview_id`、`preview_hash`、有效提案、预条件与到期时间；不提交业务变更 |
| `POST /api/v1/candidates/{c}/commit` | `preview_id`、`preview_hash`、`expected_page_version_id`、可选草稿修订；`Idempotency-Key` 请求头 | 只提交已保存预览；正文修改先重预览，全部来源/当前权限复核且候选一次消费；成功后才翻页 |
| `POST /api/v1/candidates/{c}/reject` | 请求键、理由可选 | 处置记录；项目业务图不变 |
| `POST /api/v1/projects/{p}/artifacts/uploads` 与 `POST /api/v1/uploads/{u}/complete` | 文件许可、敏感级别、大小/哈希、请求键 | 上传票据；校验后原件版本 ID 与派生状态 |

**SSE 事件信封**固定 `schema_version`、`event_id`、run 内单调 `seq`、`run_id`、`task_id`、`trace_id`、`project_id`、`input_snapshot_id`、`type`、`occurred_at` 和安全 `payload`。事件白名单为 `run.received/context_scoped/planned/started/completed/partial/failed/cancelled`、`task.started/completed/failed/retry_scheduled`、`tool.started/completed/failed`、`candidate.ready/expired/committed/rejected`、`access.changed`；斜线记法表示同一前缀下的各完整事件名。旧 route.planned、specialist.completed、validation.failed 不作为公开事件别名；校验失败归入 task/run.failed 并带安全错误类别。前端按 event_id 去重、按 seq 重放；事件只传对象引用、安全计数和错误类别，正文走授权详情接口。

### 7.2 服务内部通信

首版同步读可用进程内类型化接口；调度器向每个职责传同一冻结基底的 `TaskInput`，依赖证据结果的职责另收带引用的上游输出（`run_id`、输入版本与草稿哈希、权限快照、允许工具、证据范围、截止时间和预算），职责写独立 `AgentResult`，合成层按引用汇总。专责能力之间不互发任意自然语言消息，以免各自拿到不同 HEAD 或扩大权限。异步预览/索引/摘要失效通过业务事务同写的 `OutboxEvent` 驱动，Worker 以事件 ID 幂等消费；将来换消息代理，信封不变。文档片段始终标为**不可信资料**，其中的指令不能改变工具白名单、模型身份或写入权限。

### 7.3 错误码与状态归属

| HTTP/业务码 | 客户端必须表达 | 是否写业务对象 |
| --- | --- | --- |
| 403 `ACTION_FORBIDDEN` / 404 `NOT_FOUND_OR_HIDDEN` | 无权或不可见；不返回隐藏标题、数量、缩略图 | 否 |
| 409 `DRAFT_REVISION_CONFLICT` / `HEAD_CHANGED` | 本地编辑未覆盖；比较、重新应用或另建分支 | 否 |
| 409 `CANDIDATE_STALE` / `HEAD_CHANGED` | 候选依据旧内容；查看当时上下文或重检 | 否 |
| 410 `SOURCE_REDACTED` | 历史引用墓碑与失效原因类别；不展示原文 | 否 |
| 422 `INVALID_LINEAGE` / `INVALID_ANCHOR` | 哪条边或锚点不成立；保持预览与修正入口 | 否 |
| 503 `PROVIDER_UNAVAILABLE` / `STORAGE_BUSY` | 服务暂不可用时按安全 retryable 类别处理；原件/预览/索引各自状态另由详情响应表达 | 仅派生状态可变 |

已确认领域写响应返回 `request_id`、`project_revision`、`audit_event_id` 和新对象 ID；草稿保存响应返回 `request_id`、新的草稿修订及审计引用，不虚构新的 `project_revision`。模型错误、超时、无证据、来源冲突与候选过期要在运行域记轨迹；不得用一个通用“AI 已完成”状态遮蔽差异。

## 8 关键业务流程

### 8.1 智能体建议进入下一章

![智能体建议与人工确认业务流程图](C:/Users/MAC/Documents/ChatGPT/设计大数据基础期末作业/思诺实施规范图示/阶段建议业务流程图.png)

图 2 的事务边界从具权者确认开始。前半段只写运行域：领域入口冻结输入快照与权限→调度器先执行确定性检查、再调用必要专责能力与只读工具→合成层验证结构、证据、版本和禁令→候选卡才可进入 `candidate.ready`。后半段先显示“将创建哪一章的空白页、哪些来源边和引用”，再由用户确认。提交服务重新读取 ACL、所有来源 HEAD、草稿哈希和候选有效期；同一数据库事务插入新页 v1、来源边、明确选择的引用、决定、审计、Outbox 与幂等结果。首次 201 或幂等重放 200 确认提交后，UI 导航至已创建对象，不重复创建。拒绝只写候选处置；任何 403/409/410/422 都让页面停在变更预览，业务图不变。

### 8.2 历史版与分支

![章页节点版本切换与分支流程图](C:/Users/MAC/Documents/ChatGPT/设计大数据基础期末作业/思诺实施规范图示/版本回溯流程图.png)

图 3 把三层回溯放在同一时间坐标。项目/章选择 `project_revision`，页选择 `page_version_id`，节点在该页快照中定位 `node_id`；三个选择都是 GET。历史模式整体只读，保留“返回当前”与“从此版创建新路线”。确认分支后，服务创建新 `Page` 和 v1：可编辑节点/关系取得新 ID 和源映射，原件/证据保持确切版本引用，旧决定/测试只以历史依据显示。原页 HEAD、后续页、原测试和审阅意见不受影响。若目标是进入下一阶段，则使用 8.1 的空白页命令，不套用内容克隆。

### 8.3 上传与可引用证据

上传队列在原件完成服务器校验前只能写“传输中”；登记 `ArtifactVersion` 后写“原件已保存”，即使预览/索引仍排队。Worker 输出 `Preview`、`Extraction` 和索引片段，每条片段绑定原件版本、抽取器版本与定位；设计师可纠正 OCR，但纠正文本作为派生版本，不覆盖原件。只有设计师把片段关联到页/节点并确认，才形成业务证据边。测试必须选择确切作品版本。专业文件的可信封面标“原软件导出/系统转换/用户封面”，不能用封面暗示内部工程属性已解析。

### 8.4 并发、断线和故障

两客户端以同一草稿内容修订号保存，只有一方成功，另一方收到 409 与差异；本地编辑缓冲不得丢失。确认新页后若 SSE 或浏览器断开，客户端用 `request_id` 查询首次提交结果，不生成第二张页。预览 Worker 失败只让派生状态失败；AI 某职责超时可返回已验证的局部结果和未完成项，但不能显示完整结论。源页变化、证据撤权或对象权限收紧让受影响候选过期；UI 提供“查看当时版本”“重新检查”“从旧版创建分支”，不提供静默强制提交。

## 11 验收矩阵与客观评测方法

文档验收和系统验收必须分开。本文可检查对象、接口、权限、页面和测试是否一一对应；只有运行真实代码、固定输入与原件、保留日志后，才能报告可用性、模型表现、性能和成本。以下是实施时应冻结的验证集，延续产品稿 V01–V20，并补足草稿、章历史和记忆切换的边界。

| 编号 | 操作/故障注入 | 通过条件 | 失败证据 |
| --- | --- | --- | --- |
| I01 | 同章建两页并查看项目路径 | 两页平行，无自动前后边；图和列表一致 | 多出无依据页边 |
| I02 | 从两张来源页确认进入下一章 | 新页主体空白，保存两条确切来源版本边；拒绝时零业务改动 | 复制全部旧节点或半页 |
| I03 | 当前页草稿连改两次后用旧候选提交 | 候选按草稿内容修订/哈希失效；布局拖动不误使其过期 | 旧建议仍可采纳或布局误触发 |
| I04 | 查看章在旧 `project_revision` 的状态 | 章配置、页集合及当时版本一致；当前项目不变 | 旧章混入新页或改当前 HEAD |
| I05 | 查看节点在页 v1/v2 的内容 | 各版显示当时内容或“尚未出现/已移除” | 用最新节点回填旧版 |
| I06 | 从历史 v2 创建分支 | 新 Page/v1 可编辑起点保留源映射；原 v3、旧测试和意见不变 | 覆盖原 HEAD、复制旧测试为通过 |
| I07 | 双客户端并发改同一草稿 | 一方成功，一方 409 且本地文本保留 | 静默覆盖/丢输入 |
| I08 | 同一 `Idempotency-Key` 与相同请求正文重试建页 20 次 | 仅一页、一组来源边、一个决定；同键异体 409 | 重复业务对象 |
| I09 | 上传同名不同内容及不支持专业文件 | 两个原件版本、哈希正确；预览失败原件可回取 | 旧版覆盖或假“已保存” |
| I10 | 撤销证据权限后重连 SSE、搜索和打开缩略图 | 原文、标题、缩略图、摘要和流事件均不泄露 | 任一旁路返回敏感内容 |
| I11 | AI 无证据、冲突、超时、文档提示注入 | 返回已查范围、分歧或部分失败；业务状态不变 | 编造引用或越权写入 |
| I12 | 切 A/B 分支及本次记忆读集 | 新运行使用新快照；A 轨迹可回看但不混进 B | 上下文串线或全项目指针被改 |
| I13 | 来源页变化、证据失效后确认阶段建议 | 409/410 且无新页；可重检或从旧版分支 | 已过期候选仍提交 |
| I14 | 作品 v2 测试后上传 v3 | 测试仍指 v2，v3 显示需复核 | 浮动“最新版”使测试改指 v3 |
| I15 | 数据库/Worker/浏览器在提交边界断开 | 幂等恢复，无“已保存但无原件”、无重复页 | 孤儿业务记录或双写 |
| I16 | 从备份恢复项目 | 页版本、来源边、原件哈希、权限与审计相符；只重建派生件 | 历史或原件不可复核 |

模型效果按产品稿建议比较 B0 单助手、B1 规则加单助手、M1 路由加专责能力。冻结同一批 10–20 条真实或明确标记的模拟任务和输入版本，三组共享模型、索引、工具权限、总预算和 UI，每题重复 2–3 次。报告有效引用率、无据断言、越权访问/写入、过期候选拦截、人工修订、任务完成、p50/p95 时延、token 和费用；独立设计师/设计负责人按固定量规盲评有用性。小样本只能作为形成性证据，不能宣称显著提升设计质量。

**阻断门槛。** 任一未确认业务写入、跨项目资料泄露、撤权原件/缩略图泄露、历史版本覆盖或同一请求重复建页都阻止交付演示。准确率和时延目标须在第一轮真实基线后设定，不把本规范中的配置默认值或文档清单当作实测结果。

## 13 本轮核验后的智能体职责与依赖

本节与第 6 节共同构成首版智能体合同。四类是任务职责，不是四个常驻人格，也不要求四次模型调用。一次提问可能只需证据能力；阶段建议需要证据与过程批评；复杂简报先完成澄清运行，用户确认后，新建带 `parent_run_id` 的后续运行处理证据、方法和过程批评；后续运行重建快照并重校当前权限。一次运行按依赖选择 1–3 项；是否调度某职责由任务类型和已知缺口决定。

| 职责 | 首版覆盖 | 必须等待的输入 | 输出归属 | 后续扩展 |
| --- | --- | --- | --- | --- |
| 任务澄清 | 简报目标、边界、冲突与追问 | 冻结简报及约束 | `results.clarification` | 多方需求谈判建议列 P1 |

**旧版对照。** D 版初始化管线以 problem→knowledge→method→review 串行组织，研究提示词教练是辅助函数；E 基础版把 9 个节点放进主图，E 截止版改为 interaction↔orchestration 并在内部并发派发。两版的名称都不能直接当思诺的产品职责。E 的 `science` 带医学领域语义；`memory` 应映射成版本、检索和上下文服务；`knowledge_tree` 适合作图谱候选或只读投影。D 的概念提取、局部节点模型和任务状态界面可借鉴，写库与 API 密钥处理需要重做。静态代码证据与限制详见《思诺 D-E 智能体与并发架构核验报告》1.0。

## 14 并发、通信与一致性合同

用户关心的“多模块同时读写”，工程上分为**工作流编排、并发控制、事务边界、消息传递、幂等与一致性**。下列规则比选用 LangGraph、消息队列或特定模型更重要。

### 14.1 一次运行如何并行

领域入口先在一致性读取中确定 `base_page_version_id`、草稿内容修订与哈希、已选源作品版本、读集范围、索引修订、模板版本和授权范围，落成不可变 `ContextSnapshot`。运行中检索到的新片段及其原件版本另追加到只读结果清单，与实际索引修订一起写入运行账本；重演时按这份清单读取，不能只凭后来变化的索引重新搜索。`permission_snapshot_id` 只解释当时为何可读；每次工具请求、事件重放和候选提交仍按**当前权限**重新授权。启动后导航切页不改变运行输入。

调度器生成有向依赖图。证据与独立方法任务可以并发；需要澄清的四职责链先运行澄清并由用户确认，再开启后续运行，不在单个运行塞入四职责；方法若使用证据，则等待证据结果；过程批评必须等待其声明依赖的证据、方法和规则检查。每项任务有 `task_id`、输入哈希、截止时间、模型预算和独立输出槽，不能在共享自由字典中原地改同一个 `agent_outputs` 键。合成层只在必需任务完成或截止后运行，依据 `run_id + task_id + input_hash` 认领结果；重复或晚到结果留轨迹，不覆盖已发布候选。局部结果可展示为“部分完成”，不得包装成完整阶段建议。

专责能力之间传类型化 `AgentResult` 引用，由编排器建立依赖；自然语言仅是候选内容，不是控制消息。`TaskInput`、`AgentResult`、`Candidate` 和事件信封均带 `schema_version`、项目/运行/任务 ID、输入快照 ID、来源版本集合哈希、时间和可见性等级。未知 Schema 版本直接拒绝，并记录可诊断错误。模型文本、文件片段及工具结果均是待验证数据，不能变更消息中的授权字段。

### 14.2 写入所有权与原子边界

| 写入域 | 唯一写入者 | 同步保证 | 并发处理 |
| --- | --- | --- | --- |
| `AgentRun`、各专责结果、候选与处置 | AI 运行仓储；按独立任务键追加 | 单条结果原子；候选发布需校验依赖 | `(run_id,task_id,input_hash)` 唯一；晚到结果不覆盖 |
| 页草稿内容 | 具 `page.draft.write` 的用户经领域 API | 一次编辑操作原子 | `expected_draft_content_revision` CAS；冲突保留本地编辑 |
| 布局偏好 | 当前用户的视图状态服务 | 与内容草稿分开 | 独立 `draft_layout_revision`；不使内容候选过期 |
| 已确认页、来源边、决定和审计 | 具权者确认后的领域命令服务 | 同一数据库事务全部成功或回滚 | HEAD CAS、来源逐项复核、请求键幂等 |
| 原件字节与版本元数据 | 上传服务 | 字节先隔离暂存并校验；登记事务后可引用 | SHA-256 校验；同名新内容新版本；孤儿暂存安全清理 |
| 预览、OCR、索引、摘要 | 派生 Worker | 与原件、业务版本分开 | `(artifact_version_id,generator_version)` 去重；任务状态 CAS |

SQLite 首版只允许一个写事务在同一时刻提交；WAL 允许读写并行，**不等于多写者同时提交**。领域写事务应短小，模型调用、文件转换、外部 API 请求都在事务外。多进程部署要由数据库约束和 CAS 保证正确，进程内锁只能降低冲突。将来换 PostgreSQL 时保留唯一键、外键、版本条件更新与事务合同，不把“换库”当成已解决并发。

### 14.3 事件、重试、撤权与恢复

Outbox 与业务提交同事务。消费者以 `event_id + consumer_name` 去重，先写派生结果再确认消费；失败可重试，不能假设消息只投递一次。SSE 只发布运行进度和安全引用，订阅键必须包含租户、项目、运行和授权主体；连接建立、重连与每次回放均检查当前权限。事件序号允许断线重放，客户端按 `event_id` 去重，缺号时读取运行快照。撤权后停止推送并使预览 URL、缓存、摘要和候选失效。不能沿用 E 截止版仅按 `session_id` 广播的实现。

同一 `Idempotency-Key` 与相同请求正文重试只返回原命令结果；`request_id` 仅作追踪和结果查询关联。同键异体报 409；未知结果先查询命令状态，避免新键重试生成重复页。403、来源失效与 Schema 错误不自动重试；暂时网络故障、429、部分 5xx 使用带抖动退避且受总截止时间、次数和费用预算限制。取消运行是运行域状态，不能撤销已经完成的业务提交。恢复检查以数据库、原件清单及哈希、Outbox、派生任务账本为一组验证，不能只恢复 AI checkpoint。

### 14.4 最小故障注入用例

| 用例 | 操作 | 必须观察到 |
| --- | --- | --- |
| C01 | 两位成员基于同一草稿修订编辑同一节点 | 只有一个 CAS 成功；另一方保留差异和重应用入口 |
| C02 | 同一阶段建议双击、断网并用同一请求键重试 | 一张新页、一组边、一个决定和一致的响应 |

## 16 语言人格与验证边界

基础人格参考第二周 Iris 的“观察任务、重视材料、温和有判断力”，采用《思诺基础人格与智能体语言规范》1.0 的短提示。人格只影响表达与协作姿态；工具白名单、ACL、版本、引用、CAS、幂等和确认流程由服务端实施。四职责共享一个对外声音，运行轨迹显示实际执行职责，不让角色互相表演式对话。原稿的舞台、音乐意象及固定金句不迁入思诺。固定题集分别检验信息准确、可追源、可行动和语言自然度；没有模型试验时不能声称已去除所有 AI 痕迹。
