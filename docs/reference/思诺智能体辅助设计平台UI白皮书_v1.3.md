# 思诺智能体辅助设计平台 UI 白皮书

**产品定位：面向工业设计课程项目的 AI 辅助设计与过程管理平台**  
**版本：UI 与交互方案 1.3 勘误版｜2026 年 10 月 30 日**  
**依据：同目录《思诺智能体辅助设计平台产品白皮书》定稿 2.1**  
**文档性质：拟实施的设计规范与验证计划，不是现有界面截图说明**

## 摘要与设计决定

思诺的主界面要让设计师从一个真实设计问题出发，向智能体发出任务，查看其检索与判断过程，核对证据，再决定是否采纳。项目“书—章—页”提供稳定的工作位置；页路径图和页内图帮助回溯；资源卡承载跨软件作品。**视觉重点是可核查的智能体协作，不是把项目排成一本会翻页的书。** 首屏应让未接触产品的设计师理解“它能帮我查证据、找方法、检查方案和规划下一步；决定仍由我作”。

首版围绕五个任务设计：①提交课题并澄清未知项；②上传研究资料后询问“这条要求依据是什么”；③在同一阶段保存两张平行方案页并分别查看；④查看 AI 阶段建议、核对缺口后确认或拒绝；⑤授权审阅者沿建议打开有权限的来源和作品版本。每个任务都必须在图形视图和可访问的列表视图中完成。设计之书的翻页动效用于标明工作位置变化，不能代替版本、来源和确认状态。[W01][W02]

## 1 目标、用户与评估原则

### 1.1 UI 要解决的主要问题

现有资料、聊天、画板与专业软件各存一处，设计师难以知道 AI 建议根据哪个版本作出，也难以向设计负责人解释某条要求如何形成。UI 应把**当前问题、证据、候选行动、人工处置和历史**连成一条可见路径。画布能帮助探索，但不能让用户为得到 AI 帮助先学会复杂建模。界面默认让设计师先写问题或上传作品，再逐步补结构；专业字段在需要引用、比较或提交时出现。[W03]

### 1.2 五类主要使用者

| 角色 | 高频入口 | 最重要的界面判断 | 首版限制 |
| --- | --- | --- | --- |
| 主设计师 | 项目首页、当前页、智能体任务框 | 知道 AI 正在用哪些资料、建议会改变什么、当前版本是什么 | 可确认或拒绝获授权的建议，不被强制完成阶段清单 |
| 团队成员 | 页路径、节点评论、作品版本 | 能接续他人的判断并找到原件 | 首版仅编辑获分配的页；评论和任务交接列 P1 |
| 设计负责人或总监 | 项目审阅模式、来源索引、意见 | 在有限时间里看出证据、取舍与未验证项 | 仅在获授项目决策权时确认关键决定 |
| 资方与项目评审 | 里程碑、共享路径、意见 | 理解关键方案与风险 | 默认仅查看共享范围并留意见 |
| 上下游专业团队 | 作品版本、约束与交接卡 | 找到工程、供应链或交付依据 | 默认仅查看共享范围并留专业意见 |

项目权限由成员、对象和共享范围决定。主设计师与获授权成员编辑分配页；设计负责人、资方、项目评审和上下游团队默认只查看获共享的设计内容并可留意见。关键决定由项目配置授予的具权者确认，审阅身份不会自动开放原始访谈、保密工程文件或其缩略图；AI 候选始终需要权限与版本校验。

### 1.3 衡量方式

设计师完成来源查找、并行页创建、旧版分支、作品上传和阶段建议处置的成功率、用时、误操作与主观负担；设计负责人能否正确复述方案选择依据和未验证项。智能体卡还测引用打开率、错误引用发现率、过期状态识别率，以及用户是否理解“建议”与“已确认事实”的区别。美观评价单独收集，不能替代任务表现。正式量化提升需有基线和足够样本；首轮 3–5 名设计师与 1–2 名设计负责人或项目评审仅用于发现问题。[W04]

## 2 信息架构与导航

### 2.1 四个稳定层级

| 层级 | 页面或视图 | 用户的心智问题 | 主操作 |
| --- | --- | --- | --- |
| 项目入口 | 项目书架、最近项目、待处理 AI 候选 | 我现在该进入哪个项目？ | 新建、继续、查看待确认项 |
| 项目层 | 项目概览、阶段目录、页路径图 | 课题到了哪里，哪些路线并行？ | 打开页、查看建议、筛选路线 |
| 单页层 | 页内节点图、列表、资料侧栏、智能体工作台 | 这一页在探索什么、依据是什么？ | 提问、上传、建节点、接受候选 |
| 对象层 | 证据详情、作品版本、测试记录、运行轨迹 | 这句话/这张图/这次测试对应哪个原件？ | 打开授权锚点、比较版本、按权限留意见 |

顶部始终显示项目名、当前阶段和页、页版本、保存状态以及全局搜索。左侧为阶段和页目录；中部是当前任务与内容；右侧为智能体工作台和对象详情，避免聊天结果盖住画布。窄屏时右侧改抽屉，当前页上下文仍可辨认。项目概览与单页共享对象 ID，图和列表只是视图切换；拖动节点位置不代表建立业务关系。

界面内部维护四个互不混写的坐标：导航位置（项目/章/页）、业务读版本（已确认页版本及可选草稿内容修订）、本次 AI 运行的授权读集、当前对象焦点。章历史选择项目提交序号 `project_revision`，展示当时的章配置、页集合及页间来源边；页历史选择不可变 `page_version_id`；节点历史是在所选页快照中查看同一节点的当时状态。三种浏览均只读，不改变项目当前版、其他人的位置或正在执行的 AI 运行；历史内容仍按当前权限裁剪，撤权资料不会因选择旧时间点再次出现。具体路由及对象深链见《思诺智能体辅助设计平台 UI 页面实施规范》1.1。

### 2.2 项目书不是唯一导航

“书架—目录—翻页”可以帮助辨认位置，但每个层级保留搜索、最近访问、面包屑和列表入口。阶段是可配置活动，不是不可跳过的闯关；同一阶段的页默认平行。项目路径底层是允许分叉与合流的有类型有向图，树状布局只是默认展示。跨阶段引用、同阶段对照和来源边在视觉上区分，不能把合流硬画成唯一父节点。页内图描述设计推理，用户旅程图描述产品使用者的经历，二者名称和图例必须不同。[W01]

### 2.3 全局搜索与上下文

搜索支持项目、页、节点、原件、作品版本、证据片段和授权审阅意见；结果显示类型、所属页、版本、权限与命中位置。搜索到已过期的 AI 候选时标明生成时的页版本，并提供“查看当时上下文”。默认结果先呈现当前项目及有权限的资料，不跨项目泄露片段。任何从搜索跳转到历史页的操作都给出只读标识和返回当前页入口。

## 3 智能体工作台

### 3.1 入口与任务分流

单页顶部的主要输入写“现在想解决什么设计问题？”，旁边提供四个具体快捷动作：“澄清课题”“找依据”“选研究方法”“检查下一步”。自由提问保留，但快捷动作帮助新用户理解能力。上传研究资料、完成测试或更改任务书后，系统可在用户设置允许时生成非阻断建议；不会自行打开新页。任务提交前显示将使用的资料范围、当前页版本和可能调用的工具类型，用户可缩小范围或取消。[W02]

调度器是系统机制，UI 不把它伪装成一个会发言的“总设计师”。结果卡显示实际参与的专责能力与步骤，例如“证据检索 → 方法建议 → 过程检查”；未调用的角色不露出虚构头像。四类角色在界面中按职责命名：课题澄清、证据查找、方法建议、过程检查。用户需要的是行动与依据，角色名只作为解释运行过程的辅助信息。

自由提问和简短解释可用工作台内的聊天气泡；证据、方法、过程检查和可采纳候选用结构化卡片。运行中的步骤留在侧栏或运行详情页，不能以阻塞对话框等待。原件、证据、节点、测试与运行轨迹在可深链抽屉中追源；新页、历史分支、合流、候选确认、权限提升及最终导出用列明影响范围的确认对话框。关闭弹层不会采纳建议，成功的领域提交响应才使页面翻到新位置。

### 3.2 运行中的可见状态

运行区依次显示真实事件：“限定到当前项目及本页版本”“检索 3 份有权限资料”“核对 2 个来源锚点”“检查要求与测试缺口”“等待你确认”。每一状态可展开查看已用资料范围和失败原因。工具超时显示“证据检索暂不可用，本次仅能查看已确认项目记录”，不把局部结果包装成完整回答；允许重试或手动继续。用户关闭面板后任务可继续，回到页时从运行记录恢复状态。流式文字为过程反馈，候选已校验且状态 pending 才能显示预览入口；`candidate_ready` 是界面标签，SSE 使用 `candidate.ready`，采纳仍须服务器预览与确认。[W02]

### 3.3 结果卡的最小结构

| 区域 | 必须显示 | 用户能做什么 |
| --- | --- | --- |
| 结论 | 简短建议、对应设计问题和输入页版本 | 展开全文或切换到原页 |
| 证据 | 原件名、版本、页码/时码/区域、支持或反对关系 | 一键打开定位，查看原文与上下文 |
| 未知与冲突 | 未找到的资料、样本局限、意见不一致 | 标记待研究，补资料后重跑 |
| 候选变更 | 将新增/修改哪些节点、边或页 | 逐项选择、编辑、拒绝或稍后处理 |
| 运行说明 | 角色、工具、时间、失败与重试、运行 ID | 查看轨迹摘要，向授权审阅者解释过程 |

AI 语言用“建议”“待确认”“依据有限”等明确状态，不写“系统已经为你完成研究”。证据片段与 AI 解释分栏，避免用户把模型解释误认为受访者原话。来源失效、权限改变或页版本更新时，卡片显示过期并禁用直接采纳；保留“查看当时版本”“重新检查”“从旧版本创建分支”。没有证据时给出已查范围和建议补充的材料，不输出貌似确定的要求。[W02][W05]

### 3.4 人工确认的操作合同

只有具项目决策权限者可以点击“采纳”，随后先出现变更预览，例如“在需求定义新建一张空白页；连接用户研究 A 第 3 版与 B 第 1 版；保存你的确认”。具权者可改标题、取消某条边、选择哪些已确认要求作为引用，最后明确点击“确认创建新页”；无权者仅能查看候选并请求具权者审阅。提交时再次校验 `expected_page_version_id`、相关草稿内容修订和建议有效期；冲突时停留在预览，不静默覆盖。拒绝只写处置记录；修改后采纳保存用户修改与 AI 原提案的差异。最终导出前，用户审校来源、署名和未验证项。人工关口是控制权与可理解性设计，而不只是一个形式按钮。[W02]

### 3.5 建议频率

设置提供“关闭主动建议”“仅我请求时”“关键事件后”“定时摘要”四档。关键事件包括新证据完成索引、测试记录提交、作品版本更换、发现冲突；系统有冷却时间并把相似提示合并。必要错误告警与权限提示不受建议频率关闭影响。建议默认在侧栏或项目待办中出现；只有用户发起的任务可把工作台置前。设置页展示下一次可能触发条件，并允许用户查看或清除待处理建议。

“本次将读取”面板显示纳入的页版本、证据锚点、作品版本、方法卡与派生摘要，并允许设计师在权限内调整下一次运行的读集。一次运行启动后固定 `ContextSnapshot`；切换 A/B 路线或更改勾选不改动已确认项目事实，也不重写正在运行的快照。旧摘要须显示所依赖的来源版本；撤权后原文、缩略图、搜索摘要与流事件都应遮蔽。AI 若读取自动保存草稿，界面同时显示已确认基底和 `draft_content_revision`；内容改变会使相应旧候选过期，单纯拖动节点布局不会。

## 4 项目书、两层图与版本

### 4.1 项目概览

项目头部显示课题、目标用户、当前问题、已确认要求数、待确认 AI 候选数、最近测试与未读审阅意见。概览主区域首先展示**关键路径与分支**，每张页卡有阶段、页名、版本、方案状态、关键作品缩略图、证据完整度和未决问题数。证据完整度只表示记录覆盖，不暗示设计质量。用户可切换“路径图 / 按阶段列表 / 最近活动”。默认布局只展开当前路线与一层邻居，其余聚合为可展开组，防止大项目变成线团。[W03]

### 4.2 单页工作区

单页顶部固定“本页要回答的问题”和当前状态。中间默认显示少量有类型节点：问题、证据、洞察、要求、概念、作品、测试、决定；用户可以从自由便签转为类型节点。主树边表现本页的主要推理顺序，支持/反对/引用/测试等辅助边使用形状与文字标签，颜色只作补充。点击节点在右侧打开来源、作者、时间、相关作品与历史。节点可折叠、筛选、搜索，图过密时自动建议列表视图。初始空白页提供“写问题”“上传资料”“从上页引用已确认要求”三个动作，避免一上来显示复杂空画布。

### 4.3 翻页与分支

确认推进后，目标阶段打开一张主体内容为空的新页；来源页摘要留在侧栏，新页只存明确选择的引用，不复制整张旧图。翻页动画建议 180–260 毫秒，使用轻微横向位移和淡入来确认位置变化；在减少动态效果偏好下直接切换。返回历史页时显示“第 2 版 · 只读 · 2026-10-28”，按钮写“从此版本创建新分支”；不会出现覆盖旧页的“恢复”操作。该分支创建新的页身份，以所选旧版的可编辑节点与关系内容作为新页 v1 起点，给新节点与边分配 ID 并记录来源映射；原件和证据仍引用确切旧版本，旧决定及旧测试仅作历史依据，不自动重新确认。合并路线生成新的决定与来源边，原页仍可打开。普通放弃只改变状态，不清除历史；有授权的隐私删除走单独流程并在引用处显示失效。[W01][W06]

草稿自动保存与“保存为已确认版本”分开显示；前者递增内容修订，布局调整另记布局修订。历史只读视图、保存为版本、从旧版建分支、确认进入下一章、合法隐私删除是不同动作。任何关键写入都要在预览后由具权者确认，并由服务端复核权限、当前版本、来源有效性与请求幂等键。提交冲突保留本地编辑和预览，不播放已翻页动效。

为保持版本切换连贯，界面可在当前权限内预取邻近页版本的安全读投影，并按“页版本 + 视图”恢复缩放、筛选和对象焦点。目标版尚未加载完成时显示对应版本骨架，不能让新旧节点、标题或缩略图混在一屏。权限撤销须清理缓存和预览；预取不产生任何业务写入。切换路线时，正在执行的 AI 仍按启动时快照完成，下一次运行才使用新读集。

### 4.4 比较视图 P1

比较两页或两条路线时，以共同评价准则对齐：问题、支持证据、反例、作品版本、测试、未解决风险与设计负责人意见。差异表每项可跳原件，缺失项明确写“未记录”而非空白。智能体可以生成比较摘要，但摘要与原表并列，用户能逐项改写或拒绝。屏幕不足以容纳双列时改为逐项切换，不把字缩到难读。

## 5 资源库与专业文件

### 5.1 可视化文件夹是视图

资源库按阶段、页、方案、文件类型、作者、时间和版本筛选，同一原件可出现在多个视图而不复制文件。卡片始终显示缩略图或类型图标、原件名、格式、大小、作品版本、上传者、预览状态和引用数量。点击先开详情：预览、元数据、所连接节点和下载原件。设计师可以用“把文件关联到当前页/节点”完成整理，无需先移动到物理文件夹。测试记录只能绑定具体作品版本，修改作品后旧测试旁显示“测试针对旧版”。

### 5.2 格式级展示规则

| 类型 | 首版卡片与详情 | 不可误导之处 |
| --- | --- | --- |
| 图片、PDF | 首版原件预览、页码或区域定位、封面 | OCR 文本要能回到原件 |
| 选定的一种 3D 格式 | 首版验证可用时显示 3D 预览；其他格式先用可信封面 | 网格可看不等于尺寸、材料和制造可行 |
| 音视频、DOCX、PPTX、其他 3D 格式 | 首版保存原件并允许手动封面；自动转换按验证结果列后续版本 | 转写、字体、动画和排版可能与原件不同 |
| Figma、PSD、AI | 链接或原件卡，配导出画板/合成图 | 不承诺读取全部图层或在线编辑 |
| SolidWorks、STEP、DWG/DXF | 原件卡，配原软件导出的 PDF/PNG/GLB | 工程属性以原软件或经验证解析器为准 |
| AE、PR 工程 | 原件卡，配静帧/视频/用户封面 | 工程可能依赖外部素材、插件和版本 |

上传进度、抽取进度与预览生成分开显示。上传失败不得出现“已保存”；预览失败时原件仍可下载，提供“上传封面”和“查看错误详情”；若原件也不可用，则展示明确的完整性错误。缩略图角标“用户封面”“原软件导出”“系统转换”标识可信来源。资源详情可要求补充依赖清单，但不假装自动识别所有专业文件依赖。

## 6 项目审阅与协作

授权审阅者在共享范围内从项目摘要进入“关键路径—要求—证据—作品—测试”阅读顺序，也能打开被授权查看的历史路线。每个授权可见的 AI 建议显示来源和设计师处置；授权审阅意见绑定具体页版本或节点，并有作者时间。审阅意见不直接改写设计师记录；非作者或无相应权限者不能改写意见，设计师可回复或从意见创建待办。审阅模式默认显示已确认内容和待验证项，AI 候选单独分组，避免把机器提议误当作设计师成果。若审阅者无权查看敏感原件，显示受限原因和可用的脱敏摘要，不泄露缩略图。[W02]

首版提供成员身份与授权审阅意见；P1 再提供团队页/节点评论和任务交接。交接卡记录当前版本、决定、未解决问题和建议下一步，接收者可沿来源回看。后续开启多人编辑时若版本冲突，系统显示两方变更与可选处理；后续协作能力不以复杂的实时光标作为完成标志。

## 7 视觉语言与组件规范

### 7.1 品牌与视觉原则

“思诺”保留为产品名，正文和按钮使用清晰的设计任务语言。视觉气质建议是**安静的研究台**：浅中性色底、少量深蓝用于定位与主动作，暖色只提示待确认或风险，红色用于真正错误。书页的边缘、页签和翻动只提供轻度线索，避免把“智能体”主题做成科幻控制台。白底承载长文、来源和表格，留足注释空间。视觉系统是拟定方案，颜色需经对比度与用户识别测试后定值。[W06]

建议设计 token：背景 `#F6F7F5`、内容面 `#FFFFFF`、主文字 `#17212B`、次文字 `#52606B`、主动作 `#174C6E`、待确认 `#A9651D`、错误 `#B53B35`。这些是原型起始值，最终须测正文与控件对比度；不能只用颜色表达状态。字体优先系统中文无衬线，正文桌面 15–16 px、注释 13–14 px，长文行宽约 65–80 个汉字的等效宽度；画布标签可随缩放简化，但放大或列表模式必须能读全称。

### 7.2 组件和语义

| 组件 | 视觉与交互要求 | 数据合同 |
| --- | --- | --- |
| 页卡 | 阶段、标题、版本、缩略图、状态、来源数量 | `page_id`、`page_version_id`、状态、来源边 |
| 证据锚点 | 原件版本、页码/时码/区域、片段与上下文 | `evidence_anchor_id`、`artifact_version_id` |
| AI 候选卡 | 建议、证据、缺口、变更预览、处置 | `run_id`、输入版本、提案 ID、有效期 |
| 作品卡 | 原件和预览状态分开、版本、生成方式 | `artifact_version_id`、`preview_id` |
| 版本徽标 | 当前/历史/过期/冲突的文字与形状 | `page_version_id`、`expected_page_version_id` |
| 运行步骤 | 已完成、执行中、部分失败、待确认 | `AgentRun` 状态、角色和工具事件 |

卡片点击区域、键盘焦点、菜单项和状态文案保持一致。所有主动作采用动词加对象，例如“查看原始访谈”“从此版本创建分支”；危险操作显示作用范围。AI 结果不使用伪装成人类同伴的头像；角色可用小图标与文字说明，来源可信度由真实锚点和状态表达。

### 7.3 状态文案矩阵

| 状态 | 界面应说什么 | 可用操作 |
| --- | --- | --- |
| 空白页 | “从问题、资料或上页引用开始” | 写问题、上传、引用 |
| 资料已上传未索引 | “原件已保存，智能体暂未纳入本次检索” | 打开原件、稍后重试 |
| 智能体运行中 | “正在核对当前页第 N 版的来源” | 展开步骤、取消 |
| 无证据 | “在所选范围内未找到支持这一判断的来源” | 查看范围、补资料 |
| 证据冲突 | “两条来源对该要求给出不同信息” | 并列查看、记待验证 |
| 候选待确认 | “采纳后将新增 1 张页和 2 条来源关系” | 预览、编辑、采纳、拒绝 |
| 页版本过期 | “此建议依据的是旧版，需重新检查” | 查看旧版、重跑、分支 |
| 提交冲突 | “当前页已被更新，本次变更尚未写入” | 比较、重新应用、取消 |
| 预览失败 | “原件已保存，预览未生成” | 下载原件、上传封面、重试 |

状态文案只陈述系统确认的事实，不把“找不到”写成“该问题不存在”。错误提示还应给出下一步和保持不变的对象，例如提交冲突应说明新页未建立。

## 8 无障碍、响应式与动效

目标按 WCAG 2.2 AA 检查键盘、焦点可见与不遮挡、文本和控件对比、可操作区域、错误识别及状态通知。[W07] 两层图都提供结构化列表，键盘可按节点与关系导航；可展开树控件参考 WAI-ARIA APG 的 Tree View 模式，但页路径不是严格树，合流与跨页关系应在节点详情和关系列表里完整表达，不能用错误的 `tree` 语义掩盖图结构。[W08] 证据“支持/反对/引用”以文字或线型表达，缩略图有可读替代说明，运行中状态使用适当的实时公告而不过量播报。

桌面宽屏允许“目录—内容—智能体”三栏；普通笔记本以可收起右栏为主；平板优先列表和资源浏览；手机首版支持查看、上传、评论与处理简单建议，复杂连线编辑保留桌面端。所有尺度下，当前项目、页、版本、AI 候选状态与返回位置可见。用户设置“减少动态效果”时禁用翻页和画布自动飞行；正常动效也不改变焦点位置，不让用户因动画失去当前对象。

## 9 设计验证与实施交接

### 9.1 原型分层

先做可点击的信息架构低保真原型，检查用户是否理解“项目—阶段—平行页—节点”和“AI 候选—用户确认”；再做智能体任务与异常状态的中保真交互；最后做视觉系统和专业格式资源卡的高保真样例。每轮使用同一个具体课题与真实或明确标注的模拟材料。若低保真阶段用户已难以找到来源，就先修导航而不增加动效。[W03][W04]

### 9.2 必测任务与成功口径

| 编号 | 情景任务 | 成功口径 |
| --- | --- | --- |
| U01 | 找到“夜间取物”要求的原始访谈或照片 | 打开正确版本和定位，不把 AI 解释当原话 |
| U02 | 在用户研究阶段新增平行页 | 新页与旧页无自动先后边，能从目录分别打开 |
| U03 | 从两张研究页确认进入需求定义 | 先看候选变更，再形成空白新页与两条来源边 |
| U04 | AI 建议引用旧版本 | 识别过期、不能直接采纳，能查看旧版或重跑 |
| U05 | 上传不支持的 CAD/视频工程 | 原件仍可取回，预览状态与手动封面入口清楚 |
| U06 | 从旧方案创建分支并核对历史 | 新页继承所选旧版的可编辑内容及源映射；原路径、旧测试和审阅意见仍在；旧测试未被重签 |
| U07 | 授权审阅者核查 AI 建议 | 能在共享范围内沿卡片找到证据、设计师处置和作品版本；无权原件不泄露缩略图 |
| U08 | 只用键盘或列表完成来源查找 | 可达、焦点可见、关系文字可理解 |

研究主持人给出目标，不把按钮名称写进任务。记录完成、停顿、误解、错误、回退、主观负担和参与者原话；至少一轮包含空资料、工具失败、过期与冲突状态。对异常卡的理解可用复述题检查：“现在写入项目了吗？如果点确认会发生什么？”修订后复测关键问题。自动化无障碍检查和界面快照可发现部分问题，仍须人工键盘、屏幕阅读器与真实任务走查。[W04][W07]

### 9.3 开发交接与优先级

P0 组件为项目导航、页图与列表、证据锚点、智能体运行/候选卡、确认预览、作品版本与失败回退、授权审阅模式（设计内容只读、意见可写）。P1 为方案比较、复杂资源预览、团队交接与更丰富的数据分析。每张设计稿应附状态、文案、键盘行为、空/错/加载场景及所需数据字段；只有视觉稿没有对象合同不能交给前端。UI 与领域 API 用同一稳定 ID 和状态枚举；界面先提交 user_patch 请求服务器保存预览；确认时发送 preview_id、preview_hash、expected_page_version_id 和必要的 expected_draft_content_revision，并带 Idempotency-Key。request_id 仅用于追踪，任何提案编辑先重新预览；后端返回已提交版本或可解释冲突。AI 流式事件只更新进度组件，正式业务内容来自校验后的候选与领域提交响应。[W02]

逐页交接按《思诺智能体辅助设计平台 UI 页面实施规范》1.1 的 R01–R15 路由和 T01–T14 用例执行；后端以《思诺智能体辅助设计平台技术实施规范》1.1 的对象、权限、端点和 I01–I16 验收条件为准。形成性测试须分别记录找源成功、误入历史、错误确认、越权展示、重复写入与故障恢复；目前尚无用户测试、系统性能或模型效果实测数据，不能把本稿设计参数当成结果。

## 11 智能体工作流与界面收束（1.3 修订）

首版界面围绕设计任务组织智能体，不以角色数量展示能力。一个统一的“思诺”入口接受问题，任务状态标出这次实际调用的澄清、证据、方法和过程检查。证据与方法可以在输入相同且互不依赖时并行；过程检查等待相关结果。用户在一个地方阅读合成后的建议，并能打开每个结论的来源、版本和未完成步骤。部分失败时保留已验证内容，界面写清哪项判断尚不能作出。

R05 将画布或列表作为主工作面。页目录、对象详情、智能体任务栏和记忆读集按需打开，右侧一次只显示一个面板；R10 承载完整运行与候选，R11 承载来源目录和下一次运行读集，R06 承载版本谱系。窄屏按同一信息顺序切换全屏层。这样可以在复杂项目中保留足够的阅读面积，也让候选、业务版本和原件来源各有清楚的位置。

视觉规范以可读性为先：稳定的项目/章/页路径、明确的版本徽标、少量状态色、足够的正文和证据间距、一个主操作。翻页动画只在业务提交成功后播放；减少动效时用标题、版本和焦点变化传达同一状态。主动建议频率不影响保存、权限和原件完整性告警。人格文案采用《思诺基础人格与智能体语言规范》1.0：先回答当前问题，给来源和可执行下一步，不用固定金句或舞台比喻。此处是设计决定，仍需用原型任务和真实模型输出验证。

逐页组件、入口出口、权限与文案以《思诺智能体辅助设计平台 UI 页面实施规范》1.1 的 R01–R15、T01–T14 为准。数据与通信以《思诺智能体辅助设计平台技术实施规范》1.1 为准。首版不把概念生成、自动工程结论或全面专业文件预览写成已实现功能。
