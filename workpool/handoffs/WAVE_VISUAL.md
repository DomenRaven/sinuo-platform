# 可见交接

## 页面路径

`web/workbench.html`

用浏览器打开这一个文件。它向 `http://127.0.0.1:8000` 读取；若页面本身就从该地址打开，则用当前源。

## 它读哪些接口

- `GET http://127.0.0.1:8000/openapi.json`  
  只用来核对已挂上的 `GET /api/v1`。读到之后，某一块若出现匹配的 GET，页面只写出路径，不把未知字段画成记录。
- 不调用会写入的接口。不调用 `GET /api/v1/session`：这条读取会滑动会话并轮换 CSRF。
- 开工时路由里已有、本页不拿来填运行记录的读取：
  - `GET /api/v1/agent-runs/{run_id}/events`：单次事件流，调用前要有运行编号。
  - `GET /api/v1/projects/{project_id}/agent-runs/{parent_run_id}/fake-chain`：假模型链的步骤角色、状态和候选正文。响应里没有输入版本、错误和缺口。
  - 同路径的 `/view` 是另一页 HTML，本页不请求。

这次本机 `8000` 没有服务，浏览器里页面显示没有读到 OpenAPI，没有补运行记录或候选。

## 哪些块还没有接口

对照 `src/sinuo/api` 里现有路由。下面这些没有对应的 GET：

- 项目里的阶段。页面上的八个名字来自施工合同：任务与情境、用户与场景研究、问题及机会定义、设计要求、概念探索、深化与原型、测试与迭代、表达与复盘。
- 页内节点。七类键和合同职责写在页面上，没有读取某一页节点的接口。
- 阶段建议。`GET /api/v1/projects/{project_id}/suggestion-preferences/me` 是建议频率，本页不把它当成阶段建议。
- 运行记录。没有能返回输入版本、所走职责、错误或缺口的读取。
- 待确认候选。已有的是 `POST /api/v1/candidates/{candidate_id}/preview`、`/commit`、`/reject`。预览会写入新行。页面写明：确认前，正式页不会自己变，阶段也不会自己翻。
