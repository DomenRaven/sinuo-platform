# ADR-004 审查意见的分层关闭

日期：2026-10-30。状态：采纳。代码集成 owner：Grok 主控。

T03 审查的 N2、N3、N4 不能靠改断言关掉，也不能把触发器写成它做不到的保证。本决定不改锁定产品语义。

## 决定

1. 候选消费。行级触发器只约束每一行能否从 pending 进入终态，并要求修订加 1。它看不见 SQL 有没有 WHERE。共享写入边界是 `sinuo.application.cas.consume_candidate`：条件限定候选 ID、项目、pending 和预期修订，影响行数不是 1 就抛 `CasMismatch`，由 `write_uow` 回滚整笔事务。T09 必须调用它，不能另写一条不检查行数的更新。无 WHERE 的原始更新仍可能改多行，这是数据库边界，不是命令已实现。
2. 口令。同一口令的 Argon2 参数重哈希不增加 `auth_epoch`，也不撤销其他会话。禁用和重置必须把纪元加 1。登录在事务外验密之后，签发前用条件更新核对账号仍可用，且 `password_hash` 与 `auth_epoch` 仍是刚才验证的那一对。核对失败不签发会话，也不用重哈希覆盖期间写入的新口令。
3. 登录名。入库值仍是 NFKC、去首尾空白、casefold 之后的 1 到 64 个码位。SQLite `NOCASE` 不采用。应用连接在 `build_engine` 注册 `sinuo_login_name_canonical`。`0004` 的触发器拒绝与该函数结果不同的写入。没有注册这个函数的连接会在写入时失败，而不是静默收下未折叠的名字。直接 SQL 不会被自动折叠。
4. `jobs` 的 `succeeded`、`failed`、`cancelled`、`superseded` 不能再改状态、租约、fencing token 或 attempt。认领语句本来只接受 queued，或租约已过期的 running。`run_tasks` 的终态不能改到任何其他状态，也不能改 token 和租约。`retry_wait` 回到 `queued` 仍允许，那是合同里的重试路径。

## 迁移

没有已部署的真实库。测试库每次重建。`0003` 已在合入前改过触发器，因此追加 `0004_repair_invariants`：已停在 `0003` 的库升级到 head 时重装这几条触发器，并新增登录名与 jobs 终态触发器。降级只删除 `0004` 新增的三条触发器，不恢复可绕回的旧任务触发器，也不改 `0001` 与 `0002`。

## 验证

见本轮 pytest、冻结环境安装和 `alembic heads`。T09 仍未实现候选确认命令。
