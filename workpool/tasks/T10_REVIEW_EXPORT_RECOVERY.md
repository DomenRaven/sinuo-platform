# T10 授权审阅、快照导出与备份恢复

- 状态：planned
- 依赖：T05、T09 done
- Owner：审阅与交付开发；恢复由集成 owner 联合验收
- 基线提交或快照：认领时填写
- 写入范围：审阅意见、导出服务/Worker、备份恢复 CLI、`tests/acceptance/test_review_export_recovery.py`；共享迁移/运行配置由集成 owner 合入
- 对应门禁：G4；消费者：T11 与后续 UI 制作者

## 目标

获授权的评审可以沿项目路径查证并留下属于自己的意见；团队能导出准确版本的路径、来源、作品清单与报告草稿，并在新存储位置恢复含原件的项目历史。

## 输入与交付

意见绑定确切页/节点版本，修改需作者身份、当前权限和 revision CAS；其他人可以阅读授权意见，不能改写原话。首版完成授权审阅，普遍团队评论与交接列 P1。

导出先冻结 source manifest 和权限范围，持久任务在执行、生成与下载时重校权限。初始格式使用可读 Markdown＋JSON 清单；若总栈规定 DOCX，则提供相同来源清单的 Word 输出。可选原件包须逐件授权。来源变化后旧导出保留输入快照标识，不能冒充最新；原件缺失/墓碑明确列出。报告草稿先用有来源的确定性模板，自动方案批评和扩写仍遵守 P1 边界。

备份覆盖一致的关系库快照、原件哈希清单和必要元数据，考虑 SQLite WAL；恢复到隔离目录，重建索引/预览等派生物，再校验版本、权限、来源边和原件。合法删除/撤权的墓碑与保留策略在恢复后继续生效，不能用旧备份复活已删除敏感内容。

## 验收

创建并执行 `python -m pytest -q tests/acceptance/test_review_export_recovery.py`：

1. 非作者/失权者不能修改意见；意见指向原版本，后续版本不会静默改绑。
2. 导出范围、原件、缩略图和来源片段都服从 ACL；任务中撤权后拒绝受限内容发布/下载。
3. 断线重试同导出启动键只登记一个任务；包内 manifest 与实际文件哈希一致。
4. 在源库/原件暂不可用的隔离环境中恢复项目，页历史、分支、决定、作品哈希及权限逐项匹配。
5. 损坏备份、丢失原件和版本不兼容分别诊断，不能给假成功。
6. 测得实际备份/恢复时间和丢失范围后记录环境，不把该结果外推成生产 SLA。

## 交接与证据
