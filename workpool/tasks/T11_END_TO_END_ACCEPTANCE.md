# T11 纵向业务、并发故障与交付验收

- 状态：planned
- 依赖：T06、T10 done；夹具与用例可提前只读设计，最终判定等待全部 P0
- Owner：独立验收；最终发布判定由集成 owner 负责
- 基线提交或快照：认领时填写
- 写入范围：`tests/acceptance/` 已认领集成文件、最小演示 CLI、验收与 UI API 交接文档；实现修复退回原 owner 或重新分配
- 对应门禁：G0–G4 总验收

## 目标

在集成基线上以真实 API、数据库和文件存储跑通一个完整课题，并用可重复故障证明关键不变量。交付下一位开发者可以启动、查源、复现失败和继续做 UI 的后端，而不是仅有接口列表或一段成功录屏。

## 输入与交付

读取全部上游交接与施工验收合同，把产品 F01–F12、F16–F21 的 P0 后端行为映射到实际测试；UI 专有任务记录为待后续页面验证。为每个门禁维护通过/失败/未执行和证据链接。检查 Python/SQLite/转换器/模型配置与锁文件是否一致；fake provider 工程验证与真实模型评价分别汇报。

完整场景：创建项目/阶段/两张平行页→上传原件版本→定位证据→确认草稿版本→运行证据与过程检查→人工预览确认阶段空白页→上传作品新版本并保留旧测试→查看历史并创建分支→授权审阅→导出→隔离恢复。关键步骤同时核对 API 响应、数据库和原件哈希。

## 必须执行的验收

建立总入口 `tests/acceptance/test_end_to_end.py`，运行 `python -m pytest -q tests/acceptance`，再运行项目既有单元测试与 lint。至少保留以下反例的真实证据：

1. 同草稿双写 CAS；相同请求键重放/异体；不同键双确认同候选。
2. 事务提交边界断开；Outbox 重投；过期 Worker 回写；晚到模型结果隔离。
3. 运行中撤权、SSE 重连、历史/搜索/缩略图/回执/导出旁路访问。
4. 上传登记失败、转换器崩溃、索引落后、原件损坏与有审计墓碑。
5. 阶段新页主体空白、旧版分支保留内容映射、原 HEAD/历史/旧测试不被覆盖。
6. 从备份恢复准确历史、权限及原件，派生物可重建。

测试应控制真实顺序并验证数据库结果；不能用 sleep 假设竞态发生，不能用 mock 替代所有事务与文件行为。对于没有环境条件的真实模型/3D转换器测试写未执行与原因；相应门禁不能标为全通过。

## 最终交接

交出：启动/迁移/初始化/测试/Worker/恢复命令、OpenAPI 与事件 Schema、权限字段与错误包络、稳定对象/版本 ID、完整示例响应、演示夹具、实际测试结果、已知风险和 P1/P2 待办。UI 交接只包含消费合同和待验证任务，不制作页面、风格或交互动效。

独立审查确认没有阻断性问题后，集成 owner 在最终基线重跑并签署 G0–G4。任何未通过项写清受影响功能、复现方法和下一步；只完成工程 fake 路径时不得宣称模型效果或真实 API 已达标。
