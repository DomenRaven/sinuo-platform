# Grok 诊断与修复提示词

---

你负责诊断【任务 ID / 失败现象】。当前已经尝试：【三次以内的路径及结果】。请先核实日志、代码、环境与测试夹具，寻找新的证据；不要重复上一轮无效改法。

将问题缩小为最小可重复场景，记录预期与实际结果、版本、输入、事务/线程/进程顺序。分别检查：契约理解、依赖/API 用法、数据形态、并发时序、外部环境。每次实验只改变关键变量，用结果淘汰假设。若需修改测试，先证明原断言与冻结行为不符，并把依据交集成 owner；不能通过放宽断言掩盖实现缺陷。

优先恢复最小可运行基线，再处理优化。涉及共享接口或 schema 时给出迁移和消费者计划。无法在当前环境解决时，明确所缺的外部条件以及最小请求，同时指出仍可继续的独立任务。输出诊断证据、根因、修复 diff、针对性回归结果与后续风险；没有新证据不要宣称已经找到根因。
